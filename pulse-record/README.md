# 脉象记录表生成器

臧氏脉学 · 按讲义体例录入脉象、生成「脉象记录表」的网页工具。

> **来源**：表格体例据讲义 **2026-10 PDF p34「④ 脉象记录」** 实例表与 p48–50 空白记录表；
> 判读提示逐条出自 **讲稿 2010（民国 99 年）第十三、十四讲** 原文；
> 依脉用方骨架据讲义 **p44「依脉用方」** 与 **p46 附表一「治疗」列**，方剂组成／服法／加减／禁忌出自 **讲稿 2010 第二讲「叁、用方」「肆、依脉辨证论治」**。
> 符号定义见讲义 p33「③ 标准脉象」与 p34「④ 脉象记录」。

## 快速开始

```bash
npm install
npm run dev        # 开发：同时起前端(Vite 5180)与病例记录服务(5178)
npm run dev:web    # 只起前端（此时病例记录不可用，页面会明确提示）
npm run dev:api    # 只起病例记录服务
npm run build      # 类型检查 + 生产构建，产物在 dist/
npm run start      # 本地应用：一条命令同时提供页面与 API（读 dist/）
npm run seed:demo  # 写入 14 位演示患者（-- --reset 可先清空全部再写）
npm run preview    # 预览构建产物（静态，不含病例记录）
npm run typecheck  # 仅类型检查
```

`vite.config.ts` 里 `base: './'`，因此 `dist/` 可以直接用 `file://` 打开，便于离线使用与分享；
但**病例记录需要后端服务**（见下节），纯静态打开时该功能不可用。

## 功能

| 能力 | 说明 |
|---|---|
| 就地录入 | 点表格格子选中，再点符号按钮叠加；也可在「手输组合」直接输入 `X↑` `0+#` |
| 多记录并排 | 每加一个「日期」成一列组（左右各一），与讲义实例表同构 |
| 两种行结构 | 默认 **9 行**（寸浮中沉 / 关浮中沉 / 尺浮中沉，同实例表与空白表）；可切到 **7 脉点**（尺只沉取，同 p34「14 个脉点」定义） |
| 判读提示 | 20 条规则，全部引自讲稿原文，逐条标注讲次与原句 |
| 依脉用方 | 按录入的脉象自动比对讲义 p44「依脉用方」与讲稿第二讲 12 类脉象分型，命中条目下直接挂出**方剂卡片**（组成／服法／科学中药／适用脉象／加减／禁忌） |
| 分组维度 | 依脉开方可切换 **讲稿原序 / 按五行 / 按左右手** 三种分组；后两者逐条标出本脏·五行、兼涉本脏与**归类依据** |
| 分组筛选 | 按五行／按左右手各有一排 chip 开关（组名＋条目数＋方剂数），点一下开／关，条目与方剂备查**两处同步**，并同步到 Markdown 导出 |
| 方剂备查 | 讲稿 2010 第二讲写明的 **30 条方剂**，随分组维度一起重排，原样转录，不替读者加减方 |
| **病例记录** | **患者 → 每次就诊记录** 两级，可查看、载入编辑、改名、删除；存本机 **SQLite** 文件（永久存储，不随清缓存消失） |
| **病例搜索** | 面板内一个搜索框，**姓名 / 就诊日期 / 脉象符号**（如 `↑` `X` `\|`）三种口径同时搜；命中患者标出「命中：某日某次」 |
| **寸关尺图示** | 双手掌面图（按原图模版），把**当前日期**的脉象符号标到寸/关/尺位置；与主表双向联动 |
| 导出 PNG | canvas 自绘，色值与讲义原表一致（部位标签 `#FFC000`、表底 `#CCE8CF`、黑色网格线） |
| 导出 Markdown | 可直接落进仓库笔记层，附判读提示清单、依脉用方条目与方剂备查全表 |
| 导出 CSV | UTF-8 BOM，Excel 可直接打开 |

## 用药功能

「判读提示」面板分两个标签页：**风险提示**（脉象组合异常）与 **依脉用方**（按脉象给方）。

依脉用方的数据分三层：

| 层 | 来源 | 内容 |
|---|---|---|
| 骨架 | 讲义 2026-10 p44「依脉用方」、p46「附表一 体质分类」治疗列 | 四个挡路（挡路一 右关 / 挡路二 肝肺同治 / 挡路三 / 挡路四 尺脉）与体质用药对照 |
| 分型 | 讲稿 2010 第二讲「肆、依脉辨证论治」 | 12 类脉象分型（上盛下虚、左寸顶手、双寸浮大、右关浮大数、尺脉不平衡或过大、六脉弦细数……） |
| 方剂 | 讲稿 2010 第二讲「叁、用方」 | 30 条方剂的组成、剂量、服法、科学中药比例、加减、禁忌 |

### 分组维度

「依脉开方」页顶部有一个**分组维度**切换器，三种并存：

| 维度 | 分组 | 依据 |
|---|---|---|
| **讲稿原序**（默认） | 挡路一～六 → 讲稿方剂 → 叁、用方 → 肆、依脉辨证论治 → 用药禁忌 | 讲稿原序，便于对照讲次 |
| **按五行** | 木·肝 / 火·心 / 土·脾 / 金·肺 / 水·肾 | 五行归类出讲稿 2010·第一讲；脏位对应出讲义 2026-10·p30 |
| **按左右手** | 左手·心肝（血分）/ 右手·肺脾（气分）/ 尺脉·肾 / 双手相兼 | 讲义 2026-10·p30 的左右手脏位 ＋ 讲稿「心肝主血，脾统血」 |

脏位对应（两条资料线合看，不是自创）：

| 五行 | 本脏 | 脉位 | 原文依据 |
|---|---|---|---|
| 木 | 肝 | 左手关 | 「肝主筋」（讲义 2026-10·p30） |
| 火 | 心 | 左手寸 | 「心主脉，是唯一的火脏」（讲义 2026-10·p30） |
| 土 | 脾 | 右手关 | 「脾主肌肉」（讲义 2026-10·p30） |
| 金 | 肺 | 右手寸 | 「肺主皮毛」（讲义 2026-10·p30） |
| 水 | 肾 | 尺（双侧） | 「肾主骨」（讲义 2026-10·p30） |

切到后两个维度时，每条目右上角会标出**本脏·五行 ＋ 兼涉本脏 ＋ 主脉位**，条目下方给出**归类依据**（讲次／页码），并把同一规则的多条记录合并为一条、列出「命中记录」。
「方剂备查」那 30 条方也随维度一起重排。

两条不依脉象的**常驻条目**（三不用、上盛用白虎汤／下虚用肾气丸）在维度视图里并入「水·肾／双手相兼」，行尾标注「常驻条目（不依脉象）」。

### 分组筛选开关

按五行／按左右手两个维度下，维度切换器下方各有一排 **chip 开关**：组名 ＋ 本组条目数 ＋ 方剂数（如「木 · 肝 6条 · 8方」）。点一下开／关该组，另有「全选」「清空」两个一键按钮。

- 筛选**同时作用于依脉用方条目与方剂备查**，两处始终一致。
- 筛选状态**同步到 Markdown 导出**：导出文件里对应小节会写一行「本次导出筛选：……」，避免读的人不知道这份记录是筛过的。
- 两个维度各存一份筛选状态，互不影响；切回「讲稿原序」不设筛选（那一栏按讲次路线排列）。
- 全关时给出提示，不会留一片空白。

归属表落库于 `src/domain/grouping.ts`（61 条用方条目 ＋ 30 条方剂，覆盖率 100%）。

**边界**：只照抄讲稿原文写明的方，**不替读者加减方、不下诊断**；讲稿未写明的内容（如下焦方的服法）留空，不臆造。归类是**整理层的组织方式**，不改写原文用字与出处标注。

## 病例记录（永久存储 · SQLite）

历史记录改成**病例记录**：每位患者下挂若干次就诊记录，每次都能单独查看、单独编辑。

### 两级结构

| 级别 | 含义 | 界面 |
|---|---|---|
| 患者 | 一位受检者（姓名 ＋ 体例） | 面板第一层列表：姓名 / 就诊次数 / 最近记录时间 |
| 就诊记录 | 该患者某一天的脉象（日期标签 ＋ 这天的左右手符号） | 展开患者后的第二层列表：日期 / 记录时间 / 脉象摘要 |

**编辑方式**（主表顶部会显示当前编辑对象）：

| 当前编辑对象 | 主表显示 | 保存按钮 | 写回范围 |
|---|---|---|---|
| 某一次就诊 | 只有那一条记录 | 「保存该次记录」 | **只写回这一次**，该患者其它次不动 |
| 某位患者 | 该患者全部次记录 | 「保存该患者记录」 | 整份写回：同 id 的次记录更新、没有的删除 |
| 都不在编辑 | 当前录入的内容 | 「保存为新患者」 | 新建一位患者 |

「另存为新患者」总是新建，不覆盖正在编辑的那位。

### 搜索

面板右上角有搜索框，一个关键字同时搜**三种口径**：

| 搜什么 | 举例 | 命中范围 |
|---|---|---|
| 患者姓名 | `演示·孙` | 姓名包含关键字的患者 |
| 就诊日期标签 | `12月3日`、`3月` | 含该标签的那次就诊，其患者一并列出 |
| 脉象符号 | `↑`（顶）、`X`（细）、`\|`（弦）、`TTT` | 该次记录里出现过该符号的，其患者一并列出 |

- 命中患者下方标出「**命中：12月3日、1月21日**」，看得出是靠哪几次记录命中的。
- 展开某位患者时，若他是靠**次记录**命中的，只列命中的那几次（标题写「只显示命中的 N 次」）；若是靠**姓名**命中的，照常列出全部次记录。
- 搜不到时提示「没有匹配「xxx」的患者或就诊记录。」；输入框旁的 `×` 一键清空。
- 搜索走后端 `GET /api/search?q=…`（防抖 180 ms），不扫全库。

### 存盘位置

```
pulse-record/local-data/history.sqlite
```

- **不写浏览器 localStorage**：清缓存、换浏览器、换机都还在；文件可直接用 `sqlite3` 命令查、可拷贝备份。
- 用 Node 22+ 内置的 `node:sqlite`，**无原生模块、无第三方依赖**；首次运行自动建库建表（表结构见 `server/schema.sql`）。
- `local-data/` 是运行产物，已在 `.gitignore` 里，不进版本库。

### 表结构

| 表 | 列 | 说明 |
|---|---|---|
| `patients` | `id` / `name` / `layout` / `created_at` / `updated_at` | 一位患者；`layout` 为 `nine`（9 行）或 `seven`（7 脉点） |
| `visits` | `id` / `patient_id` / `label` / `at` / `pulse_values` / `seq` | 一次就诊记录；`pulse_values` 是 JSON，key 形如 `L\|寸\|浮`，值为符号代码数组（如 `["X","↑"]`） |

删患者会级联删掉其全部就诊记录（`ON DELETE CASCADE`）。

### 演示数据

`npm run seed:demo` 会写入 **14 位演示患者**（名字统一以「演示·」开头，便于一眼分辨、一键清理）及其每次就诊记录，脉象符号照讲义 p33–34 的符号集填。

- **可重复执行**：默认先清掉已有的「演示·」患者再写，不会越堆越多；加 `-- --reset` 连非演示患者一起清空。
- 覆盖 8 套符号模式（平和／肝郁／上盛／肾虚／顶手／肝郁弦／细脉／变脉），其中弦 `|`、细 `X`、变脉 `#`/`TTT`/`DDX` 可直接拿来验证**按符号搜索**。
- 体例两种都有：`nine`（9 行）与 `seven`（7 脉点，尺只沉取）。
- 就诊时间用固定基准时刻推算，重复执行结果一致（可复现）。

数据落在同一个 `local-data/history.sqlite` 里，`sqlite3` 可直接查：

```bash
sqlite3 local-data/history.sqlite \
  "select name, layout, (select count(*) from visits v where v.patient_id=p.id) from patients p;"
```

### API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 连通性 ＋ 数据库路径 |
| GET | `/api/patients` | 患者列表（含就诊次数） |
| GET | `/api/search?q=…` | 搜索：姓名／日期标签／脉象符号，附带 `matchType` 与命中次记录 |
| GET | `/api/patients/:id` | 一位患者 ＋ 其全部就诊记录 |
| POST | `/api/patients` | 整份保存（患者 ＋ 就诊记录） |
| PATCH | `/api/patients/:id` | 重命名患者 |
| DELETE | `/api/patients/:id` | 删除患者（级联删其就诊记录） |
| GET/PATCH/DELETE | `/api/visits/:id` | 取／改／删一次就诊记录 |

开发时 Vite 把 `/api` 代理到 `http://127.0.0.1:5178`；`npm run start` 时由服务端同端口托管页面与 API。
服务没起时，页面会明确提示「连不上本地病例记录服务……请用 npm run dev 起前后端」，**不会静默丢数据**。

## 表格版式

按讲义 p34 实例表的像素结构复刻（详见仓库根 `AGENTS.md`「④ 实例表的版式结构」）：

| 要素 | 本工具的画法 |
|---|---|
| 表头 | 两行。**第一行只放日期**，每组横跨「左 + 右」两列，中间不画竖线；第二行放「左 / 右」 |
| 姓名 | 在**表头第二行**，横跨「部位 + 取法」两列，左缘与部位列对齐；正上方留白、不画框线 |
| 部位列 | 橙色 `#FFC000`，纵向合并一组三行，组内不画横线；组界横线贯穿橙列且加粗 |
| 取法列 | 只在正文（浮 / 中 / 沉） |
| 表底 | `#CCE8CF`，网格线 `#000000`；数据列等宽（原表随日期文字长度变宽，此处统一） |

DOM 表格与 PNG 导出共用同一套几何规格（部位列 54 px、取法列 54 px、数据列 66 px、表头行 42 px、正文行 40 px）。

## 符号体系

| 符号 | 含义 | 符号 | 含义 |
|---|---|---|---|
| `0` | 无 | `↑` | 顶 |
| `-` | 弱 | `\|` | 弦 |
| `+` | 有 | `#` | 变脉（忽大小） |
| `±` | 有（比有弱） | `TTT` | 跳调停 |
| `++` | 有力 | `DDX` | 大大小（忽快慢） |
| `±±` | 有力（比有力弱） | `X` | 细 |
| `+++` | 很有力 | | |
| `++++` | 非常有力 | | |

一格可叠加多个符号，如 `X↑`、`0+#`。

## 两条资料线的关系

本工具只处理**讲义 2026-10** 的脉象记录表体例。2010 讲稿提供的是**判读规则**（体质分型、依脉辨证论治）与**方剂资料**，
两套体质命名体系不同，详见仓库根目录 `AGENTS.md`「两条资料线的真实差异」——**不要把两套命名混用**。

依脉用方里两线并存、各自标注出处：讲义 p44 / p46 的条目标 `讲义 2026-10·pNN`，讲稿第二讲的分型与方剂标 `讲稿 2010·第二讲`。

## 边界

工具只标出讲稿明确点名的脉象组合及其原文表述，**不构成诊断**；临床判断请由持证医师作出。

**已知限制**：讲义 p34 的符号集没有「数 / 迟 / 软」代码，只有力度（`0` `-` `+` `++` `↑`）与 `|`（弦）、`X`（细）、`#`（变脉）。
