# 脉象记录表生成器

臧氏脉学 · 按讲义体例录入脉象、生成「脉象记录表」的网页工具。

> **来源**：表格体例据讲义 **2026-10 PDF p34「④ 脉象记录」** 实例表与 p48–50 空白记录表；
> 判读提示逐条出自 **讲稿 2010（民国 99 年）第十三、十四讲** 原文；
> 依脉用方骨架据讲义 **p44「依脉用方」** 与 **p46 附表一「治疗」列**，方剂组成／服法／加减／禁忌出自 **讲稿 2010 第二讲「叁、用方」「肆、依脉辨证论治」**；
> 方剂的**成方配伍与克数**出自 **《臧氏脉学方剂汇总统表（同和堂版）》**（纸质讲义 4 页，原图在 `../data/臧氏脉学方剂汇总统表（同和堂版）/`）。
> 符号定义见讲义 p33「③ 标准脉象」与 p34「④ 脉象记录」。

## 快速开始

```bash
npm install
npm run dev        # 开发（默认单机模式）：同时起前端(Vite 5180)与病例记录服务(5178)
npm run dev:multi  # 开发（多用户模式）：要注册/登录，病例按账号隔离
npm run dev:web    # 只起前端（此时病例记录不可用，页面会明确提示）
npm run dev:api    # 只起病例记录服务
npm run build      # 共享包编译 + 类型检查 + 生产构建，产物在 dist/
npm run build:core # 只编共享包（小程序端用，产物在 miniprogram/utils/core/）
npm run start      # 本地应用：一条命令同时提供页面与 API（读 dist/）
npm run seed:demo  # 写入 14 位演示患者（-- --reset 可先清空全部再写）
npm run admin      # 账号维护命令行（list / create / reset / role / wechat …）
npm run preview    # 预览构建产物（静态，不含病例记录）
npm run typecheck  # 仅类型检查
npm test           # 全量回归（共享包冒烟 + 小程序静态检查 + 老库迁移回归 + 越权隔离 + 浏览器回归 + 桌面端）
```

`vite.config.ts` 里 `base: './'`，因此 `dist/` 可以直接用 `file://` 打开，便于离线使用与分享；
但**病例记录需要后端服务**（见下节），纯静态打开时该功能不可用。

- 使用与构建说明：**[`docs/desktop.md`](./docs/desktop.md)**

> U 盘把 exe 和 `data\` 一起带走，换台电脑打开，病例还在。
> 安装版的病例库在 `%APPDATA%\臧氏脉学\`。两者各用各的，互不影响。

## 账号与多用户

有两种模式，`/api/health` 的 `mode` 字段会明说是哪一种，页头也有「单机模式／多用户」标识：

| 模式 | 启动 | 登录 | 数据 |
|---|---|---|---|
| **单机** | `npm run dev`（默认） | 不用登录 | 只有一个内置账号，病例互不隔离（就是原来的用法） |
| **多用户** | `npm run dev:multi` | 要注册/登录 | **按账号隔离**，两个账号互不可见、互不可改 |

- 账号模型：**一个 `users` 行 ＝ 一个「人」**，登录方式挂在 `identities` 上
  （`password` 登录名／`wechat` openid／`local` 单机）。
- 令牌是**不透明随机串**，用 `Authorization: Bearer` 头传（**不用 cookie**，天然免疫 CSRF），
  有效期 30 天、滑动续期、可吊销；改密码会清空本人全部会话。
- **跨用户访问一律 404，不用 403** —— 403 会泄露「这东西存在」。
- 密码用 Node 内置 `crypto.scrypt`（N=16384/r=8/p=1）＋ `timingSafeEqual`，**不引第三方依赖**。
- 登录名规则：**11 位手机号**，或 **4~20 位字母开头的字母数字下划线**（手机号本期只作登录名，不发验证码）。
- 老库迁移是幂等的：四张业务表补 `owner_id` → 重建 `custom_symbols` → 建 `local` 账号 → 回填 →
  **三条 owner 不变量自检**（任一不为 0 就在启动时报错）。迁移前自动留 `history.sqlite.bak-<ts>`
  （用 SQLite 的 `VACUUM INTO` 取一致性快照，含 WAL 里的数据）。
- **老数据要有人认领**：单机时代录的病例在升级到多用户后归在内置 `local` 账号名下，新注册的账号
  看不到（隔离是对的，但数据得转过来）：
  `npm run admin -- claim <登录名>` —— 数据一个字节没改，只把归属换给该账号。
- 维护账号：`npm run admin -- list | create <登录名> | reset <登录名> | role <登录名> admin | wechat <登录名> | claim <登录名>`。
- 反向操作（把某账号的数据转给内置单机账号，桌面版导入老数据时用）：
  `npm run admin -- claim-local <登录名>`。

## 部署

上线手册在 **[`docs/deploy.md`](./docs/deploy.md)**（服务器初始化、systemd、Caddy、备份与恢复演练、
小程序发布清单、备案办理）。要点：

- **ICP 备案是整条时间线上最长的一段**（7~20 工作日），**第一天就启动**；
  域名实名主体必须与小程序主体一致（个人主体 → 个人实名）。
- 反向代理用 Caddy（自动 HTTPS）；**对外只暴露 443** —— 微信 request 合法域名不接受端口。
- 网站与 API 同一进程托管 → **同源，不需要 CORS**。
- 备份用 `sqlite3 .backup`（**不是 cp** —— WAL 下直接复制可能拿到半截事务），每日 03:00、保留 30 天；
  **每月做一次恢复演练**（备份文件「存在」不等于「能用」）。
- 访问日志**只记方法/路径/状态/耗时/user id，不含请求体**（病例数据敏感）。

迁移到 CloudBase 的规划见 **[`docs/cloudbase-migration.md`](./docs/cloudbase-migration.md)**。

## 微信小程序

`miniprogram/` 是原生小程序工程，**功能对齐网站**，两端共用同一个后端、同一套账号、同一份数据。

```bash
npm run build:core   # ① 编共享包（知识库 + 绘制代码），再打开微信开发者工具
```

- 用**微信开发者工具**打开 `pulse-record/miniprogram` 目录。
- `miniprogram/utils/config.js` 里改 `API_BASE`（本机联调填 `http://127.0.0.1:5178`，
  局域网联调填电脑 IP 并在开发者工具勾「不校验合法域名」；上线填已备案的 https 域名）。
- `miniprogram/project.config.json` 的 `appid` 换成真实小程序 AppID。
  **AppSecret 绝不入小程序包** —— 它只放在服务器的 `/etc/pulse-record.env`。
- 账号打通：小程序 `wx.login` → 服务端 `code2Session` → 没绑过就引导输入「网站账号＋密码」绑定
  → 绑定后两端看到**同一份病例**。

**共享包**（两端同源的关键）：`src/domain/**` 与 `src/export/text.ts` 零 DOM 依赖，整棵子树用
`tsc` 编成 CommonJS 搬进小程序；`src/export/png.ts` 拆成**纯绘制器**
（`table-painter.ts` ＋ `diagram.ts` ＋ `canvas.ts`）与 DOM 驱动两部分，
小程序用**同一份绘制代码**（canvas 2d），所以**小程序存到相册的图与网站导出的图版式完全一致**。

个人主体的硬约束：`code2Session` 可用；**`web-view` 不可用**（不支持业务域名）→ 必须原生开发；
**`getPhoneNumber` 不可用** → 账号绑定只走「网站账号＋密码」。

## 桌面应用（规划中 · 尚未实现）

计划把本工具打成 **Windows 桌面应用**（`.exe` 安装包 ＋ 免安装版），数据模型是
**单机、免登录、只在这台电脑上**（无账号、无云端、无同步；数据落在本机用户目录的 SQLite 文件里）。

**技术路线是 Electron，但业务逻辑一行不重写**：桌面壳只做三件事——起服务进程、开窗口、管导出另存为；
渲染进程跑的就是**原封不动的 `dist/`**，`server/` 也是现有那份（零第三方依赖，只用 node: 内置）。

- **实施方案全文**：**[`docs/desktop-plan.md`](./docs/desktop-plan.md)**
  （含已核实的 Electron 版本→内置 Node 映射、架构图、**逐文件改动清单**、风险表、验证计划、里程碑）
- **各工作线进度**：**[`docs/progress.md`](./docs/progress.md)**

现状：**方案已成，实现一行未写**，开发分支 `chore/desktop-electron`（基点 `b9e3b19`）。

三个容易踩的坑，实现前先看一眼 `desktop-plan.md`：

1. **Electron 版本下限 35** —— `node:sqlite` 要 Node ≥ 22.13（22.13 解除 `--experimental-sqlite` flag），
   Electron ≤ 34 内置的是 Node 20，**用不了**。
2. **SQLite 库不能放 asar 内** —— asar 只读，而 SQLite 要写 WAL/SHM；必须落在
   `app.getPath('userData')` 下。
3. **老数据拷过去会「看不到」** —— 业务表按 `owner_id` 归属，本机 70 行数据在 `guoguo` 名下，
   而桌面端单机模式一律挂 `local`，直接拷 `.sqlite` 过去只会显示 0 行。
   方案 §5.3 给了「导入数据文件」的解法。

## 部署与自检

本机全功能版（页面 + 病例记录 API 同端口，一个进程）：

```bash
npm install
npm run build      # 产物在 dist/
npm run start      # 单端口应用：页面与 API 都在 5178
npm run seed:demo  # 写入 14 位「演示·」患者（需服务已在跑，该脚本走 HTTP 接口）
```

打开 <http://127.0.0.1:5178/> 即为本机全功能版。`dist/` 也能直接双击 `index.html` 离线用，只是病例记录那部分不可用。

自检三步：

1. `curl http://127.0.0.1:5178/api/health` → `{"ok":true,"db":"…/local-data/history.sqlite"}`；
2. 页面左上「病例记录」按钮上的数字＝患者数（演示数据下应为 14），说明前端已从后端取到列表；
3. 面板搜索框依次试 `↑`、`X`、`演示·` —— 符号、姓名、日期标签三种口径都应命中。

> **注意**：右侧内置浏览器（Electron 沙箱）打开本机页面时，页面内的 fetch 会被 CORS 拦掉，病例记录面板显示「Failed to fetch」。那是浏览器沙箱的限制，**不是服务没起**；用 Chrome / Edge 正常打开同一个地址即一切正常。

| **表下体质行** | 主表底部一行「体质」：**每个记录日期各记各的**（体质随治疗推进会变）；点格子就地选体质（顺带显示它对应的疗法），与 ① ② 同一套存库 |

| 依脉用方 | 按录入的脉象自动比对讲义 p44「依脉用方」与讲稿第二讲 12 类脉象分型，命中条目下直接挂出**方剂卡片**（组成／服法／科学中药／适用脉象／加减／禁忌） |

| 分组筛选 | 按五行／按左右手各有一排 chip 开关（组名＋条目数＋方剂数），点一下开／关，条目与方剂备查**两处同步**，并同步到 Markdown 导出 |
| 方剂备查 | 讲稿 2010 第二讲写明的 **30 条方剂**，随分组维度一起重排，原样转录，不替读者加减方；另附**同和堂版《方剂汇总统表》** 45 条成方 ＋ 17 条「科中」 |
| **配伍与剂量** | 讲义 p42「依脉用方表」28 行**加了「配伍与剂量」列**：同和堂版成方（药味＋**克**）与讲稿组成（**比例制**）可切换或并列对照，两套**不互相换算** |
| **剂量五个入口** | 同和堂版的克数在**③开方药清单、用药记录每行、p42 对照表（默认展开）、依脉用方条目本身、方剂备查（三个维度都显示）**五处都能直接看到，不用翻折叠块 |

## 开方三部曲（整个工具的主框架）

讲义 2026-10 PDF **p47（印刷页码 45）**「臧氏脉学 开方三部曲」图是**整个工具的主框架**——
**原图就放在页面最顶端**（点一下可放大看），下面三步照它的次序走。

```
讲义 p47 原图（置顶，点开放大）
┌──────────────────────────────────────────────────────────────┐
│ ①判体质 摸脉 → 判断方式 → 状态   ← 体质手选 + 主表 / 符号录入 / 寸关尺图示 │
├──────────────────────────────────────────────────────────────┤
│ ②定疗法 按体质定疗法              ← 疗法手选 + 判读提示（风险提示 / 依脉用方）│
├──────────────────────────────────────────────────────────────┤
│ ③开方药 按疗法列方                ← 开方药清单 ＋ 用药记录      │
└──────────────────────────────────────────────────────────────┘
        ⟲ ③ 之后回到 ① 重新判体质（讲义 p47 图上的虚线回路）
```

### ① ② 由使用者自己选

**工具不代判体质、不代判疗法。** 两条问句（有变脉？／尺脉弱？）只作**参考**：框头会标出
命中的格子（可点击定位），但不决定体质、也不写进记录。

| 操作 | 结果 |
|---|---|
| 在 ① 点一个体质 | 记下该体质，并**按图上的配对带出**②的疗法（②里标「随体质带出…」） |
| 在 ② 换个疗法 | 只改疗法，**①的体质不动** |
| ① 的「清除」 | 体质与疗法一起清掉（疗法是随体质带出的） |
| ② 的「清除」 | 只清疗法，体质保留 |
| ③ 的开方药 | 只按**所选疗法**列 p47 图上那一支的方名；没选疗法就提示先在 ② 定疗法 |

选好的体质与疗法**按每次就诊存进本机 SQLite**（`visits.constitution` / `visits.therapy`），
下次载入该患者会还原。

### 表下的「体质」行（每个日期各记各的）

体质会随治疗推进变化，**同一个人前后两次就诊的体质可能不同**，所以主表底部有一行「体质」，
**每个记录日期各记各的**（讲义 p34 原表没有这一行，是工具自己加的）。

| 操作 | 结果 |
|---|---|
| 点某一列的体质格 | 就地展开三个体质（每个下方带出它对应的疗法）＋「清除」；**同时把这一列设为当前日期**，① 框的体质、② 框的疗法随之对上这一列 |
| 选一个体质 | 该次就诊记下这个体质，并按图上的配对带出疗法（可在 ② 改） |
| 「清除」 | 该次就诊的体质与疗法一起清掉 |

它与 ① ② 是**同一份数据**（`visits.constitution` / `visits.therapy`），
只是 ① ② 走「当前日期」这条线，表下这一行走「逐次就诊」这条线。
体质与疗法**不进导出**（PNG / Markdown / CSV 均不含），只在页面与病例库里。

### 三步的状态怎么推进

| 步 | 判定条件 | 状态 |
|---|---|---|
| ①判体质 | 这次**录了脉象** | 已完成 |
| ②定疗法 | **自选**了体质 | 已完成 |
| ③开方药 | ②完成后**这次记了方** | 已完成 |

1. 看一眼页首的流程图（点开放大）；

3. 在②里确认或改疗法；
4. ③里照图列出开方药，在下面填实际用了什么方、加减、服法。

### 边界

- **不代判、不下诊断**：体质与疗法是使用者自己判断后记下的；参考判据只标位置，不下结论。

### 分组筛选开关

按五行／按左右手两个维度下，维度切换器下方各有一排 **chip 开关**：组名 ＋ 本组条目数 ＋ 方剂数（如「木 · 肝 6条 · 8方」）。点一下开／关该组，另有「全选」「清空」两个一键按钮。

- 筛选**同时作用于依脉用方条目与方剂备查**，两处始终一致。
- 筛选状态**同步到 Markdown 导出**：导出文件里对应小节会写一行「本次导出筛选：……」，避免读的人不知道这份记录是筛过的。
- 两个维度各存一份筛选状态，互不影响；切回「讲稿原序」不设筛选（那一栏按讲次路线排列）。
- 全关时给出提示，不会留一片空白。

归属表落库于 `src/domain/grouping.ts`（61 条用方条目 ＋ 30 条方剂，覆盖率 100%）。

**边界**：只照抄讲稿原文写明的方，**不替读者加减方、不下诊断**；讲稿未写明的内容（如下焦方的服法）留空，不臆造。归类是**整理层的组织方式**，不改写原文用字与出处标注。

## 方剂的配伍与剂量

讲义 **2026-10·p42** 的「依脉用方表」28 行，原表只有「**处方 ｜ 对应脉象及加减**」两列 —— **没有组成与剂量**（已逐页核过 PDF p42）。
这份表要能抄得走，就得有药味与克数。工具把它拆成三份资料各管一维：

| 维度 | 资料 | 单位 |
|---|---|---|
| 方 ↔ 脉象 | 讲义 2026-10·p42（28 行）、p44 依脉用方图 | —— |
| 方 ↔ 组成／服法／加减／禁忌 | 讲稿 2010·第二讲「叁、用方」 | **比例制**（如「熟地5、茯苓4」） |
| 方 ↔ 成方（药味＋克） | **《臧氏脉学方剂汇总统表（同和堂版）》**（纸质讲义 4 页） | **克** |

### 在页面上怎么看

剂量在**五个入口**都能直接看到，不用再翻：

| 入口 | 看什么 |
|---|---|
| **③开方药清单** | 每条方名下并列两套：同和堂版（克）＋ 讲稿 2010（比例制），各带出处 |
| **③用药记录 · 每行** | 填了方名就在该行下方列出两套组成（宽屏行内、窄屏在表下方整宽列出） |
| **③用药记录 · p42 对照表** | 「讲义 2026-10·p42「依脉用方表」原文对照（28 行）」**默认展开**，表头是 `# ｜ 处方 ｜ 对应脉象及加减 ｜ **配伍与剂量** ｜ 操作` |
| **依脉用方 · 条目本身** | 每条命中条目按方名补上两套剂量（讲义 p44／p46 出头的条目原本只有方名） |
| **依脉用方 · 方剂备查** | 「同和堂版《臧氏脉学方剂汇总统表》」分组**三个维度下都显示**（按五行／按左右手时也在，只是注明不参与分组筛选） |

p42 对照表里「配伍与剂量」列上方还有**剂量来源**切换：

- **同和堂版（克）**（默认）—— 成方药味＋克数＋第 4 页「科中」比例
- **讲稿 2010（比例制）** —— 组成／服法／科学中药／加减／禁忌
- **两套并列** —— 两套同时列出，各自标出处

每格底部有一行**「对照：…」**，写明这一行讲义 p42 与哪套资料的哪个方是同方对照，依据是什么。

**两套剂量单位不同，不可互相换算、也不合并。** 默认只显示一套，避免看混。

### 按方名查组成的口径

各处（③清单、用药记录行、依脉用方条目、方剂备查）共用 `src/domain/dose-lookup.ts` 一份实现：

| 情形 | 界面上的说法 |
|---|---|
| 完全同名 | 直接列组成 |
| **讲义 p42 的显式对照**（讲义方名 ↔ 同和堂版方名，登记在 `FORMULA_REFERENCE`） | 标明「**别名对照（有明确对照依据）**」，并写出依据（讲义第几行 · 依据原文） |
| 讲稿侧的**别名对照**（`FORMULA_ALIAS` 里有依据的对照，如讲义「天王芪」↔讲稿「左寸浮大 · 脉数（天王补心丹加芪）」） | 标明「别名对照（有明确对照依据）」，**走在候选之前** —— 讲稿里同名的方不止一张，对照表指了哪张就用哪张 |
| 同名不同号（该资料方名里含这个名字，如「上焦方」↔「1号/2号/3号上焦方」） | 列**全部**候选，标明「同名不同号 N 条（原方名各不相同，工具不替你选）」 |
| **组合方不作候选**（名字带「+」，如「双关+参苏」） | 组合方是**另一个方**，不拿来顶替单方 |
| **单味药不作候选**（查询词恰是候选方组成里的一味药，如「黄芪」之于「黄芪鳖甲」） | 排除该候选；查的就是一味药时直接明说「未载」 |
| **方名后面的括号／加法写法不算方名**（「天王芪（天王补心丹 + 黄芪）」「六神散 + 陈皮 + 黄芪」） | 去掉后半截再查一次，并写明「按前段「X」查到」 |
| 查不到 | 明说「**未载**」，不拿名字相近的方顶替 |

举例：在用药记录里填「加味理中」，同和堂版给出「加味理中汤」一条（**别名对照**，写明讲义 p42 第 10 行的依据），讲稿给出五脏疗法的「右关虚脏 · 软而无力（加味理中）」一条（**别名对照**）—— 三焦疗法的「中焦方（加味理中）」是**另一张方**，工具按对照表指的那张来，不替你乱选。

### 依脉用方的条目自己也带剂量

讲义 p44「依脉用方」图与讲稿第四讲的**挡路**条目，原文只给**方名**（如「右关浮软 → 六神」「尺脉不平衡 → 知柏六味桂」），没给组成。以前这些条目在页面上只有方名，**剂量是欠的**；现在按方名补上：

| 条目 | 补什么 |
|---|---|
| 讲义 p44／p46 出头的条目（**没有**讲稿方剂卡片） | 同和堂版（**克**）与讲稿 2010（**比例制**）**两套并列**，各带出处与对照依据 |
| 已有讲稿方剂卡片的条目 | 讲稿那一套由卡片负责，只补**同和堂版（克）**，避免重复 |

## 病例记录（永久存储 · SQLite）

历史记录改成**病例记录**：每位患者下挂若干次就诊记录，每次都能单独查看、单独编辑。

### 两级结构

| 级别 | 含义 | 界面 |
|---|---|---|
| 患者 | 一位受检者（姓名 ＋ 体例） | 面板第一层列表：姓名 / 就诊次数 / 最近记录时间 |
| 就诊记录 | 该患者某一天的脉象（日期标签 ＋ 这天的左右手符号） | 展开患者后的第二层列表：日期 / 记录时间 / 脉象摘要 |

**编辑方式**（主表顶部会显示当前编辑对象）：

| 当前编辑对象 | 主表显示 | 保存按钮 | 写回范围 |
|---|---|---|---|
| 某一次就诊 | 只有那一条记录 | 「保存该次记录」 | **只写回这一次**，该患者其它次不动 |
| 某位患者 | 该患者全部次记录 | 「保存该患者记录」 | 整份写回：同 id 的次记录更新、没有的删除 |
| 都不在编辑 | 当前录入的内容 | 「保存为新患者」 | 新建一位患者 |

「另存为新患者」总是新建，不覆盖正在编辑的那位。
它是**复制**一份：复制出来的就诊记录与用药记录会**换新的 id**，原患者那几次记录不会被搬到新患者名下（原患者仍保有自己的记录）。

### 新增记录的日期

工具条「新增记录」用的是**日期选择器**（原生 `<input type="date">`），不是自由文本框。

| 项 | 约定 |
|---|---|
| 默认值 | **今天**（本地时区） |
| 日期标签 | **年月日六位**（YYMMDD）：公历后两位年 ＋ 月 ＋ 日，如 `261102` ＝ 2026 年 11 月 2 日 |
| 提示 | 选择器下方实时显示将写入的六位标签（如「日期按年月日六位记，如 **261102**」） |
| 落库 | 该次记录的 `visits.at` ＝ **所选日期当天 00:00**（本地时区）的时间戳，病例列表按它排序，不是按录入时刻 |
| 改名 | 六位标签可在「已有记录」chip 里直接改（如改成「2月5」），改标签不改 `at` |

- 讲稿／讲义正文用**民国纪年**（99 年 ＝ 2010），那是引用原文时的写法；「新增记录」记的是当下录人的日期，**按公历记，不折算民国纪年**。
- 同一天可以有多次记录，标签重复也没关系；要区分就在 chip 里改名。
- 相关代码：`src/domain/dates.ts`（`todayYmd` / `ymdToLabel` / `ymdToTimestamp`）。

### 搜索

面板右上角有搜索框，一个关键字同时搜**三种口径**：

| 搜什么 | 举例 | 命中范围 |
|---|---|---|
| 患者姓名 | `演示·孙` | 姓名包含关键字的患者 |
| 就诊日期标签 | `12月3日`、`3月` | 含该标签的那次就诊，其患者一并列出 |
| 脉象符号 | `↑`（顶）、`X`（细）、`\|`（弦）、`TTT` | 该次记录里出现过该符号的，其患者一并列出 |

- 命中患者下方标出「**命中：12月3日、1月21日**」，看得出是靠哪几次记录命中的。
- 展开某位患者时，若他是靠**次记录**命中的，只列命中的那几次（标题写「只显示命中的 N 次」）；若是靠**姓名**命中的，照常列出全部次记录。
- 搜不到时提示「没有匹配「xxx」的患者或就诊记录。」；输入框旁的 `×` 一键清空。
- 搜索走后端 `GET /api/search?q=…`（防抖 180 ms），不扫全库。

### 存盘位置

```
pulse-record/local-data/history.sqlite
```

- **不写浏览器 localStorage**：清缓存、换浏览器、换机都还在；文件可直接用 `sqlite3` 命令查、可拷贝备份。
- 用 Node 22+ 内置的 `node:sqlite`，**无原生模块、无第三方依赖**；首次运行自动建库建表（表结构见 `server/schema.sql`）。
- `local-data/` 是运行产物，已在 `.gitignore` 里，不进版本库。

### 表结构

| 表 | 列 | 说明 |
|---|---|---|
| `patients` | `id` / `name` / `layout` / `created_at` / `updated_at` | 一位患者；`layout` 为 `nine`（9 行）或 `seven`（7 脉点） |
| `visits` | `id` / `patient_id` / `label` / `at` / `pulse_values` / `seq` / `constitution` / `therapy` | 一次就诊记录；`pulse_values` 是 JSON，key 形如 `L\|寸\|浮`，值为符号代码数组（如 `["X","↑"]`）；`constitution` / `therapy` 是**使用者自选**的体质（肾虚／上盛下虚／平和）与疗法（三焦疗法／五脏疗法／一体疗法），未选为 `NULL` |
| `medication` | `id` / `patient_id` / `visit_id` / `seq` / `name` / `pulse` / `symbols` / `adjust` / `usage` / `note` / `created_at` | 一条**用药记录**（使用者的实际用药），挂在某一次就诊下；一次就诊可多条。`pulse` 是对应脉象的**文字**，`symbols` 是对应脉象的**符号**（JSON，key 同 `visits.pulse_values`：`手\|部位\|取法`），两者并存 |
| `custom_symbols` | `code` / `name` / `created_at` | 使用者自建的符号（如 `S`＝涩）；讲义固定符号集之外另加 |

删患者会级联删掉其全部就诊记录（`ON DELETE CASCADE`），就诊记录删除则级联删掉其用药记录。

### 演示数据

`npm run seed:demo` 会写入 **14 位演示患者**（名字统一以「演示·」开头，便于一眼分辨、一键清理）及其每次就诊记录，脉象符号照讲义 p33–34 的符号集填。

- **可重复执行**：默认先清掉已有的「演示·」患者再写，不会越堆越多；加 `-- --reset` 连非演示患者一起清空。
- 覆盖 8 套符号模式（平和／肝郁／上盛／肾虚／顶手／肝郁弦／细脉／变脉），其中弦 `|`、细 `X`、变脉 `#`/`TTT`/`DDX` 可直接拿来验证**按符号搜索**。
- 体例两种都有：`nine`（9 行）与 `seven`（7 脉点，尺只沉取）。
- 就诊时间用固定基准时刻推算，重复执行结果一致（可复现）。

数据落在同一个 `local-data/history.sqlite` 里，`sqlite3` 可直接查：

```bash
sqlite3 local-data/history.sqlite \
  "select name, layout, (select count(*) from visits v where v.patient_id=p.id) from patients p;"
```

### API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 连通性 ＋ 数据库路径 ＋ 当前模式（`single`／`multi`） |
| POST | `/api/auth/register` | 注册 `{loginName, displayName, password}` → `{user, token}`；登录名已存在 → 409 |
| POST | `/api/auth/login` | 登录 `{loginName, password}` → `{user, token}`；密码错 → 401（不区分「用户不存在」与「密码错」） |
| POST | `/api/auth/logout` | 删当前会话 |
| GET | `/api/auth/me` | 当前登录者 ＋ 微信绑定状态 |
| POST | `/api/auth/change-password` | 改密码 `{oldPassword, newPassword}`；改完清空本人全部会话 |
| POST | `/api/auth/wechat/login` | 小程序 `wx.login` 的 code 换会话：`{status:'bound', user, token}` 或 `{status:'need_bind'}` |
| POST | `/api/auth/wechat/bind` | 用网站账号＋密码把微信身份绑到该账号 `{code, loginName, password}` |
| DELETE | `/api/auth/wechat` | 解绑微信身份 |
| GET | `/api/patients` | 患者列表（含就诊次数） |
| GET | `/api/search?q=…` | 搜索：姓名／日期标签／脉象符号，附带 `matchType` 与命中次记录 |
| GET | `/api/symbols` | 自定义符号清单（使用者自建） |
| POST | `/api/symbols` | 新增／改名自定义符号 `{code, name}` |
| DELETE | `/api/symbols/:code` | 删除自定义符号（不动历史记录） |
| GET | `/api/patients/:id` | 一位患者 ＋ 其全部就诊记录 |
| POST | `/api/patients` | 整份保存（患者 ＋ 就诊记录 ＋ 用药记录） |
| PATCH | `/api/patients/:id` | 重命名患者 |
| DELETE | `/api/patients/:id` | 删除患者（级联删其就诊记录与用药记录） |
| GET/PATCH/DELETE | `/api/visits/:id` | 取／改／删一次就诊记录（PATCH 可带该次的 `medications`） |
| GET | `/api/patients/:id/medication` | 该患者的全部用药记录 |
| POST | `/api/patients/:id/medication` | 整份覆盖该患者的用药记录 |
| GET | `/api/visits/:id/medication` | 某一次就诊的用药记录 |
| POST | `/api/visits/:id/medication` | 只覆盖该次就诊的用药（其它次不动） |
| DELETE | `/api/medication/:id` | 删一条用药记录 |

**除 `/api/health` 与三个登录/绑定接口外，所有 `/api/*` 都要带 `Authorization: Bearer <token>`**，
未登录一律 401，**绝不降级成「公共只读」**。

开发时 Vite 把 `/api` 代理到 `http://127.0.0.1:5178`；`npm run start` 时由服务端同端口托管页面与 API。
服务没起时，页面会明确提示「连不上本地病例记录服务……请用 npm run dev 起前后端」，**不会静默丢数据**。

## 用药记录（填写表 · 暂不进导出）

主表下方新增一块**用药记录**：按**每次就诊**分组，使用者自己填这一次**实际用了什么方、加减、服法**。

| 项 | 约定 |
|---|---|
| 形态 | **填写表**。不是自动判读，也不是处方建议 —— 工具不替使用者加减方、不下诊断 |
| 表格样式 | **与「病例记录」表同一套**（共用边框／表头底色／字号规则）：表头一行「方名 / 对应脉象 / 加减 / 服法 / 备注 / 操作」，每次就诊一张表，分组之间用虚线分隔 |
| 列 | 方名 / 对应脉象 / 加减 / 服法 / 备注 / 操作（× 删除） |
| **对应脉象** | **文字与符号并存**：文字自己填（如「右关弱且左关有」），符号从该次记录里挑（如 `右关 沉 ++ 有力`），两者同时记、同时显示；符号选完，文字**自动带过来**（详见「右 → 左自动填入」） |
| 选择器 | 方名与对应脉象两格各有「选择」入口，弹出**两列**面板（见下） |
| 一次就诊 | 可记**多条方**（对服、并行、上中下焦分服都记得下） |
| 存哪 | 本机 SQLite 独立 `medication` 表，挂在 `visits` 下面（`visit_id` 外键，删就诊记录则级联删其用药） |
| 写入语义 | 与病例记录一致三种：患者级**整份覆盖**（同 id 更新、没有的删除）／单次级**只写回那一次**／新建时随患者一次写入 |
| 导出 | **暂不纳入**导出（PNG / Markdown / CSV 均不含用药记录），只在页面上能用 |

### 选择器（弹窗，两列）

点「方名」或「对应脉象」格里的**选择**，弹出面板：

| 列 | 内容 | 说明 |
|---|---|---|
| **左：处方** | 讲义 p42「依脉用方表」28 行（序号 ＋ 处方 ＋ 对应脉象及加减） | 点一行即回填**方名**与**对应脉象的文字**；方名仍可自己改 |
| **右：脉象** | **该次就诊录到的**符号，按脉位筛选：全部／左寸／右寸／左关／右关／左尺／右尺 | 点一下即把该脉点的符号并入这一行的「对应脉象」；每项都带讲义 p33 的文字（如 `++` 有力） |

- 左列的**搜索词与页面下方「原文对照」表共用** —— 原来的筛选方式照旧能用，两处同步；在下方搜「右关」，弹窗里也是「右关」。
- **右 → 左单向联动**：右列点脉位（选右关）→ 左列搜索框**自动填「右关」**，左列跟着看讲义 p42 里对应的方；点组合按钮 → 左列填该组的原文检索词（双关同治→双关、肝肺同治→左关右寸、肝心同治→左寸关…）。

- 右列只列**录到符号**的脉点；该脉位这次没录，就明说「该脉位这次没有录到符号」。
- 选中的符号在格子里以小徽标显示（位置 ＋ 符号 ＋ 文字），弹窗底部也列一遍，可「清空符号」。

### 右 → 左自动填入

右列选完符号，「对应脉象」的**文字**自动写进表格里的那一格 —— 左边不用再打一遍；但**仍可自己写**。

- 自动文字形如「**肝肺同治**（右寸 浮 + 有；左关 浮 ++ 有力）」：带上你点的那一组的名字 ＋ 各脉点的符号与讲义 p33 文字。
- 没手改过时标「按符号生成」，符号一变就跟着重写；**手改过**后标「已手改」，符号变动**不再覆盖**，旁边给一个「按符号重填」由使用者决定要不要改回去。
- 弹窗页脚实时预览「自动写入左格「对应脉象」：……」，写之前就看得见会填什么。
- 从左列选处方会把**原文**的对应脉象（如「右关弱且左关有」）写进文字格 —— 那算自己写的，符号变动不再覆盖。
- 只填了「对应脉象」而没填方名的行**照样存**（整行全空才会被丢掉），不会在保存时静默消失。

### 与「依脉用方」的区别

两者并存，**不互相替代**：

| | 依脉用方（判读面板） | 用药记录（本表） |
|---|---|---|
| 谁写的 | **工具**按录入的脉象自动比对出来的 | **使用者**自己填实际用了什么 |
| 依据 | 讲义 p44 / p46 ＋ 讲稿第二讲 | 使用者的临床判断 |
| 内容 | 讲稿写明的方剂的组成／服法／禁忌 | 实际用的方、加减、服法、备注 |
| 性质 | 原文照录的**参考** | 使用者的**记录** |

| 要素 | 本工具的画法 |
|---|---|
| 表头 | 两行。**第一行只放日期**，每组横跨「左 + 右」两列，中间不画竖线；第二行放「左 / 右」 |
| 姓名 | 在**表头第二行**，横跨「部位 + 取法」两列，左缘与部位列对齐；正上方留白、不画框线 |
| 姓名与日期标签的字号 | PNG 导出按格子宽度**自适应**：放不下先缩字号，最小 11 px 仍放不下则截断加 `…`，**不越格、不压到「左」列** |
| 部位列 | 橙色 `#FFC000`，纵向合并一组三行，组内不画横线；组界横线贯穿橙列且加粗 |
| 取法列 | 只在正文（浮 / 中 / 沉） |
| 表底 | `#CCE8CF`，网格线 `#000000`；数据列等宽（原表随日期文字长度变宽，此处统一） |

DOM 表格与 PNG 导出共用同一套几何规格（部位列 54 px、取法列 54 px、数据列 66 px、表头行 42 px、正文行 40 px）。

## 符号体系

| 符号 | 含义 | 符号 | 含义 |
|---|---|---|---|
| `0` | 无 | `↑` | 顶 |
| `-` | 弱 | `\|` | 弦 |
| `+` | 有 | `#` | 变脉（忽大小） |
| `±` | 有（比有弱） | `TTT` | 跳调停 |
| `++` | 有力 | `DDX` | 大大小（忽快慢） |
| `±±` | 有力（比有力弱） | `X` | 细 |
| `+++` | 很有力 | | |
| `++++` | 非常有力 | | |

一格可叠加多个符号，如 `X↑`、`0+#`。

## 自定义符号（可自建，如「涩」＝S）

讲义 p33–34 的固定符号集（`0 - + ± ++ ±± +++ ++++ ↑ | # TTT DDX X`）**一个字不改**；固定集之外，使用者可以自建符号。

| 项 | 约定 |
|---|---|
| 在哪建 | 「符号录入」面板 → 自定义符号组 → **＋ 添加**，填「名称」与「代码」两项（如 名称 `涩`、代码 `S`） |
| 代码规则 | 1~3 个字符，不含空格与「/」，**不得与讲义固定符号重复**（前后端各校验一次） |
| 存哪 | 本机 SQLite（`custom_symbols` 表），与病例记录同一套永久存储，换浏览器/换机都还在 |
| 能干什么 | 点它即可录进当前格；手输组合能解析它（`SZ`）；寸关尺图示同步显示；PNG / Markdown 导出自动带图例 |
| 边界 | 自定义符号**不参与**讲稿判读与依脉用方的比对 —— 讲义讲稿里没点名的符号，工具不会替它推断 |
| 删符号 | 删掉只影响符号表，**已录入的历史记录保留原代码**；导出时该代码会标成「已从符号表删除」，读表的人不至于看到一个没解释的符号 |

导出图例的位置：PNG 在表格**下方白底一条**（表格本体仍是讲义 p34 版式，一个字没动）；Markdown 在表格下方一行 `> 自定义符号：…`。

## 两条资料线的关系

本工具只处理**讲义 2026-10** 的脉象记录表体例。2010 讲稿提供的是**判读规则**（体质分型、依脉辨证论治）与**方剂资料**，
两套体质命名体系不同，详见仓库根目录 `AGENTS.md`「两条资料线的真实差异」——**不要把两套命名混用**。

依脉用方里两线并存、各自标注出处：讲义 p44 / p46 的条目标 `讲义 2026-10·pNN`，讲稿第二讲的分型与方剂标 `讲稿 2010·第二讲`。

## 边界

工具只标出讲稿明确点名的脉象组合及其原文表述，**不构成诊断**；临床判断请由持证医师作出。

①判体质、②定疗法的**体质与疗法是使用者自己判断后点选的**，工具只记录、不代判；自动标出的「有变脉？」「尺脉弱？」仅作**参考**（标出命中位置，不决定体质、不写进记录）。

**已知限制**：讲义 p34 的符号集没有「数 / 迟 / 软」代码，只有力度（`0` `-` `+` `++` `↑`）与 `|`（弦）、`X`（细）、`#`（变脉）。
因此讲稿「浮大数」「浮大软」这类分型，工具只能按力度与 `|`、`X`、`↑` 近似判定，无法完全自动区分——对应条目在页面上已如实标注。
