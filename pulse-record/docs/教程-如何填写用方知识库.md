> 面向审核者：你手上有讲稿（2010）、讲义（2026-10）、同和堂版方剂表三份原始资料，
> 要把它们审完、录进工作簿。这一篇讲**从原文到格子**的每一步。

**配套材料**

| 文件 | 是什么 |

| `content/示例-填写示范.xlsx` | **练习册** —— 主工作簿的副本，有 5 格故意留空给你练 |

| 工作簿里的「说明」sheet | 每张表的列说明与填写约定（悬停列头也有批注） |

## 0. 先弄清三件事

### 0.1 这份表格是什么

它是**人工编辑层**。程序真正读的是仓库里的 `src/content/*.json`。

```
   你改这份工作簿  ──►  跑一条命令  ──►  JSON 变了  ──►  网站／小程序读 JSON
   （人填的）            转回命令
```

所以：**改内容就改工作簿**，别改 JSON（改了会被转回去覆盖）。
工作簿里的内容最终会变成程序里显示的东西 —— 填错就是显示错。

### 0.2 三条铁律

| 铁律 | 说明 |
|---|---|
| **主键不要动** | ID／用字／符号／条目ID 这几列被别的表引用，改了就对不上 |
| **留空＝原文没写** | 不是「还没填」。空着不补 —— 别替读者补写讲稿没有的东西 |
| **照抄原文，不改写** | 方名、用字、条件文字都是原文用语。改写就是篡改资料 |

### 0.3 两条资料线、两个单位（最容易搞混的）

| | 讲稿 2010 | 讲义 2026-10 | 同和堂版 |
|---|---|---|---|
| 在哪张表 | 方剂·讲稿2010、用方条目 | 讲义p42用方表、矩阵 sheet | 成方·同和堂版 |
| 剂量单位 | **比例制**（「熟地5」「茯苓4」） | —— | **克**（「茯苓12」） |
| 体质命名 | 肾虚／上盛下虚／有尺脉 | 1 号／2 号／3 号 | —— |

⚠️ **比例制和克不可换算、不可合并。** 同和堂版的「茯苓12」不是讲稿的「茯苓4」的另一种写法。

## 1. 五分钟上手

**第一次填，先做一遍这样的往返**：

```bash
cd pulse-record

# ① 改完工作簿，转回 JSON
npm run content:json

# ② 确认转回的内容与工作簿一致（没有信息在途中丢失）
npm run content:check

# ③ 跑全量测试
npm test
```

三条命令都在 `pulse-record/` 目录下跑。

**改之前先备份**：Excel 里另存一份，或者 `git checkout pulse-record/content/` 就能回到原样。

## 3. 符号：看不懂 `++` 就查「符号表」

「脉象用字」表里会出现这些代码。它们出自讲义 2026-10 p34：

| 符号 | 名称 | 符号 | 名称 |
|---|---|---|---|
| `0` | 无 | `↑` | 顶 |
| `-` | 弱 | `\|` | 弦 |
| `+` | 有 | `#` | 变脉 |
| `±` | 有（比有弱） | `TTT` | 跳调停 |
| `++` | 有力 | `DDX` | 大大小 |
| `±±` | 有力（比有力弱） | `X` | 细 |
| `+++` | 很有力 | | |
| `++++` | 非常有力 | | |

「脉象用字」表还多一列 **「符号含义」**（如 `大或顶` → `+＝有；±＝有（比有弱）；↑＝顶`），
这一列是**自动算出来的，只读** —— 要改含义去「符号表」改「名称」。

### ⭐ 用字 ≠ 符号代码

这是最容易搞错的一处：

| | 是什么 | 例子 |
|---|---|---|
| **符号代码** | 该格**允许**的取值集合 | `++`、`±±`、`↑` |
| **用字** | 讲稿／讲义**写下**的那个词 | 「大」「大或顶」「虚脏」「顶手」 |

矩阵的格子里填**用字**。想填什么，先看「脉象用字」表第 1 列有哪些用字，照抄。

## 4. 分表填写细则

### 4.1 方剂·讲稿2010（讲稿第二讲，30 方）

| 列 | 填什么 | 注意 |
|---|---|---|
| ID | 英文短标识 | **主键，别改** |
| 方名 | 讲稿原名 | 不改成现代教材方名（「二仁茯茯」就是「二仁茯茯」） |
| 疗法 | 一体疗法／三焦疗法／五脏疗法 | 讲稿的分类 |
| 组成 | 讲稿原样，顿号分隔 | **比例制**：「熟地5、茯苓4」 |
| 服法 | 讲稿原话 | |
| 科学中药比例 | 讲稿另列的比例 | |
| **加减** | 讲稿写明的条件式加减 | **一条一行**（见 §4.1.1） |
| 适应脉象 | 讲稿写的脉象 | 原文用语 |
| 禁忌 | 讲稿写的禁忌 | 逐条照抄 |
| 出处 | 「讲稿 2010·第二讲（…）」 | 必填 |
| 原文引述 | 讲稿原句 | 转述不加引号，逐字引用才加 |

#### 4.1.1 一格多条 → 一条一行

「加减」经常有好几条。**同一格内换行分隔**，一条一行：

```
尺脉没有力量的，记住要加干姜0.3g
尺脉有力的，黄芪易防风0.3g
```

⚠️ **不要用顿号或逗号分隔。** 讲稿的方名自带顿号：

> 「柴鳖骨（柴胡、鳖甲、地骨皮）」

用顿号切，必然切错。

### 4.2 成方·同和堂版（49 方）

| 列 | 填什么 | 注意 |
|---|---|---|
| ID | 英文短标识 | 主键 |
| 方名 | 表上的原名 | |
| **组成（克）** | 照录，单位**克** | 与讲稿的比例制是两套 |
| 原文备注 | 表上写的备注 | 原文写错的字也照录（如「茯苓卷12」） |
| 页码 | 原表第几页 | |

### 4.3 科学中药比例 ＋ 成方↔科中对照

「科中」表列的是各成方的科学中药比例；对照表说明**哪个成方用哪条比例**。

### 4.4 讲义p42用方表（28 行）

讲义 p42 的「处方 ｜ 对应脉象及加减」两列，**只有处方名与脉象，没有组成**。
照录即可。

### 4.5 脉象用字 ＋ 符号表

「脉象用字」= 原文用字 → 它允许的符号集。
「符号表」= 讲义固定符号集（14 个），**符号的字面不改**。

### 4.6 脉位组合（7 组）

双关同治、肝肺同治、双寸…… 讲稿／讲义写明的**部位组合**，方便一次选多个脉位。
「成员脉位」格式：`L|关`（手|部位），一条一行。

### 4.7 用方条目（61 条）

**这是全套的骨架** —— 每条用方条目配一张脉象图。

| 列 | 填什么 | 注意 |
|---|---|---|
| ID | 英文短标识 | **主键**；与「脉象图·条目」一一对应 |
| 路线 | 肾虚／上盛下虚／挡路一…／讲稿方剂／用药禁忌 | |
| **触发条件** | **原文用语** | 不改写、不概括 |
| 治法 | 原文的治法 | |
| 方剂 | 方名，一条一行 | |
| 添加药 | 是「往主方里加什么药」，**不是方名** | 一条一行 |
| 关联方剂ID | 对应「方剂·讲稿2010」的 ID | 一条一行 |
| 出处 | 「讲义 2026-10·p44（…）／讲稿 2010·第N讲」 | 必填 |
| 原文引述 | 原文引述 | |
| 类别 | 主线／加味／禁忌／常驻 | |

### 4.8 脉象图·条目（50 行）—— 图名的真源

每条用方条目一行，是 50 张矩阵的**索引**。

| 列 | 填什么 | 注意 |
|---|---|---|
| 条目ID | 英文短标识 | **主键**；与「用方条目」一一对应 |
| **图名** | 这张图是**哪个方子**的（如「清挡路」） | 矩阵 sheet 的 tab 名＝`P序号-图名`，改完见下 |
| 出处 | 「讲义 2026-10·p44（…）／讲稿 2010·第N讲」 | |
| 与条件文字的出入 | 讲义与讲稿不一致处 | 有则写，无则空 |

⭐ **图名用原文用词**（讲稿的方名／讲义 p42、p44 的用语），不改写成现代教材方名。

⚠️ **改图名要跑两条命令**：

```bash
npm run content:json     # Excel → JSON（图名进 JSON）
npm run content:excel    # JSON → Excel（tab 名跟上）
```

只跑 `content:json` 会让 tab 名与图名对不上 —— 这时 `npm run content:check`
会报「sheet 名与图名不一致」并提醒你重跑 `content:excel`。
（转移命令**不会**因此报错，否则就死锁了：改了名 → 转移报错 → 新名进不了 JSON → 没法重生成。）

### 4.9 脉象图：矩阵 sheet（P04-清挡路 … P50-肝心同治·挡路六）

**矩阵是脉象图的唯一编辑面。**

```
第 1 行    顶部提示（填写说明摘要）
第 2 行起  表头区：条目ID｜路线｜触发条件｜出处｜与条件文字的出入｜关系型要求
列头行     部位｜取法｜左手｜右手｜左组号｜右组号｜左格备注｜右格备注｜左柔性｜右柔性
9 行数据   寸(合并3行) 浮中沉 ｜ 关(合并3行) 浮中沉 ｜ 尺(合并3行) 浮中沉
```

👉 想看这张表**长什么样**（图里画的就是真实的 P04「清挡路」）—— 打开
[`填写流程图.html`](./填写流程图.html) 第 03 节。

| 列 | 填什么 | 注意 |
|---|---|---|
| 部位／取法 | —— | **只读**，三个部位各合并三行 |
| **左手／右手** | **用字**（如「大或顶」） | 照抄「脉象用字」表第 1 列；**留空＝原文没提这一格** |
| **左组号／右组号** | 组号数字 | 见下 |
| 左格备注／右格备注 | 这一格原文的具体话（如「浮大而软」） | 没有就空着 |
| 左柔性／右柔性 | `TRUE` | 见下 |

#### 4.9.1 组号：同号＝且，异号＝或

组号就是 **AND 组的编号**：

| 你看到的 | 意思 |
|---|---|
| 两格**同一个数字** | 同一组 —— 组内是「**且**」（两格都要满足） |
| 两格**不同数字** | 不同组 —— 组间是「**或**」（满足一组即可） |
| 填了用字、组号**留空** | ❌ **不允许** —— 读回时会报错（见下） |

⚠️ **左右两列的组号共用同一个编号空间** ——

- 左关写 `1`、右关写 `2` ⇒ **两组** ⇒「左关满足 **或** 右关满足」
- 左关写 `1`、右关也写 `1` ⇒ **同一组** ⇒「左关**且**右关都要满足」

（`双关同治`、`左关右寸浮大` 这类「两个位置一起」的条件就是同号；
`上盛下虚` 这种「哪一边都行」的就是异号。）

⚠️ **填了用字就必须填组号**（1、2、3…）。不填的话，这一格会被**悄悄丢出所有组**：
图上还显示着那个用字，看着像有要求，判定时其实**不作数** —— 所以还原脚本直接报错。

#### 4.9.2 柔性：TRUE 是什么意思

填 `TRUE` ＝「本格还须配合表头的『关系型要求』才成立」。
不填 ＝ 本格自己就能成立。

关系型要求是**画不成单格**的条件（「忽大忽小」「跳跳停停」「尺脉不平衡」这类），
写在表头区，条目「脉象图·关系」表里有完整版。

#### 4.9.3 表头区只有「条目ID」能看，其余是只读副本

「路线／触发条件／出处／与条件文字的出入／关系型要求」都是**从别的表抄来的**，
标了「（只读）」。真源在：

- 路线／触发条件／出处 → **「用方条目」表**
- 关系型要求 → **「脉象图·关系」表**

要改，去那两张表改。

⚠️ **sheet 名里的序号（P01、P02…）不要改** —— 那是这条条目在「脉象图·条目」表里的位置。
条目 ID 最长 35 字符，Excel 的 sheet 名上限是 31 会被截断，所以靠序号认人。

⚠️ **sheet 名里的图名（方剂名）可以改，但要去「脉象图·条目」表改** ——
改那一行的「图名」列，然后依次跑：

```bash
npm run content:json     # Excel → JSON（图名进 JSON）
npm run content:excel    # JSON → Excel（tab 名跟上）
```

只跑 `content:json` 会让 tab 名与图名对不上 —— 这时 `npm run content:check`
会报「sheet 名与图名不一致」并提醒你重跑 `content:excel`。
（转移命令**不会**因此报错，否则就死锁了：改了名 → 转移报错 → 新名进不了 JSON → 没法重生成。）

### 4.10 脉象图·关系（39 行）

画不成单格的条件。| 列 | 填什么 |
|---|---|
| 条目ID | 对应「脉象图·条目」的 ID |
| 关系种类 | 如「尺脉不平衡」「任意格变脉且无力」 |
| 原文用语 | 讲稿／讲义原话 |
| 探针格位 | `L|寸|浮` 这样的格键 |
| 探针符号 | **逗号分隔**（如 `++,++`） |

⚠️ **同一关系有多个探针时，每行各填自己的。**
不要「只在第一行填、其余留空」—— 那样会被当成续行，探针就**静默丢了**。

### 4.11 脉象图·格位 —— ⚠️ 派生的，不要改

它是各矩阵摊平后的样子，**转回 JSON 时以矩阵为准**，这里改了会被覆盖。
要改脉象，去 `P04-清挡路` / `P05-引火归元·上盛下虚` … 矩阵 sheet。

## 5. 三个完整例子

> 例子里的原文都能核对。练手请用 `content/示例-填写示范.xlsx`（练习册）。

### 例 1：补一条讲稿明写的「加减」

**原文**（讲稿 2010·第二讲（六）左寸浮大（脉数）末尾）：

> 「加减。尺脉没有力量的，记住要加干姜0.3g；尺脉有力的，黄芪易防风0.3g。」

**填进哪**：「方剂·讲稿2010」表 → ID = `zuocun-fuda-tianwang` 的行 → 「加减」列。

**填什么**（一条一行）：

```
尺脉没有力量的，记住要加干姜0.3g
尺脉有力的，黄芪易防风0.3g
```

**转回后**：`drugs.json` 里这一条的 `adjustments` 会是这两项组成的数组。

### 例 2：改一个矩阵格位

**要改哪**：`P04-清挡路` → 「关浮」那一行 → 「左手」列。

**填什么**：**用字**，不是符号代码。比如 `大`（不是 `++`）。

**怎么确认用字对不对**：看「脉象用字」表第 1 列有没有这个用字。
写了表里没有的字，转回时会报 `用字「xxx」不在「脉象用字」表里`。

### 例 3：组号怎么填

`P04-清挡路` 的左手三格（寸浮／关浮／尺浮）都是第 **1** 组，
右手三格都是第 **2** 组 —— 所以「左关满足 **或** 右关满足」。

**填法**：左手那三格的「左组号」都填 `1`，右手那三格的「右组号」都填 `2`。

⚠️ 如果两格是「且」关系（两格都要满足），它们填**同一个数字** ——
**左右都一样**：左格和右格都填 `1`，它们就是同一组。
（例：`双关同治` 的左右关都填 1；`左关右寸浮大` 的左关、右寸都填 1。）

## 6. 常见报错对照

还原脚本**宁可报错也不猜**。看到这些信息，照下表改：

| 报错 | 怎么改 |
|---|---|
| `主键（id）为空` | 那一行的 ID 被清空了 —— 补回，或删掉整行 |
| `主键「xxx」重复` | 两行用了同一个 ID —— 改掉其中一个 |
| `条目ID「xxx」在「脉象图·条目」里不存在` | 引用了没有的条目 —— 检查 ID 拼写 |
| `用字「xxx」不在「脉象用字」表里` | 写了表里没有的用字 —— 照抄「脉象用字」表第 1 列 |
| `组号「xxx」不是正整数` | 组号只能是数字 —— 留空或填 1、2、3 |
| `表头写的条目ID 是「xxx」，但序号 NN 对应的是「yyy」` | 矩阵 sheet 被改名或移动了 —— **序号不能改** |
| `矩阵里没有条目「xxx」的 sheet` | 少了一张矩阵 —— 50 条条目都要有 |
| `关系「xxx」原文用语前后不一致` | 同一条关系的几行「原文用语」写得不一样 —— 统一 |
| `部位为空（合并单元格上溯失败）` | 矩阵的部位列被拆开了 —— 恢复合并 |
| `填了用字「xxx」但没填组号` | 这一格会被悄悄丢出所有组 —— 补上组号 |
| `sheet 名与图名不一致` | 改了「图名」但没重跑 `content:excel` —— 跑 `npm run content:excel` |

## 7. 练手：练习册

`content/示例-填写示范.xlsx` 是主工作簿的副本，有 **5 格故意留空**并标黄，
每格旁边写了批注：这一格该填什么、依据哪句原文。

```bash
# ① 打开练习册，把 5 格填了
# ② 验收（逐格告诉你填对没有、差在哪儿）
npm run content:exercise:check

# ③ 想重新练一遍
npm run content:exercise
```

练习点：

| # | 位置 | 练什么 |
|---|---|---|
| E1 | 方剂·讲稿2010 → `zuocun-fuda-tianwang` → 「加减」 | 一格多条，一条一行 |
| E2 | 成方·同和堂版 → `th-1` → 「组成（克）」 | 同和堂版用克 |

⚠️ **别对练习册跑 `npm run content:json`** —— 里面有故意留空的格子，

## 8. 纪律（一条都不放松）

1. **方名照录** —— 不改成现代教材方名。两条资料线叫法不同的**并列**登记，不替读者选一个。
2. **剂量不换算** —— 讲稿比例制与同和堂版的克是两套。
3. **出处必标** —— 每条都带出处。
4. **转述不加引号** —— 只有逐字引用才加引号。
5. **讲稿没写的一律留空** —— 不补写、不臆造。
6. **不替读者加减方、不下诊断** —— 页面已声明「不构成诊断」。
7. **三套资料线不合并** —— 讲稿／讲义／同和堂版各自标注，体质命名体系不互换。

## 9. 卡住了怎么办

| 症状 | 先看 |
|---|---|
| 不知道某列什么意思 | 悬停列头看批注；或「说明」sheet |
| 不知道 `++` 是什么 | 「符号表」sheet |
| 不知道矩阵某格该填什么 | 「脉象用字」表第 1 列；或该条的「原文引述」 |
| 转回报错 | §6 报错对照表 |
| 填完发现改错地方了 | `git checkout pulse-record/content/` 回到原样（记得先存你的改动） |
| 想确认没改坏别处 | `npm run content:check` ＋ `npm test` |
