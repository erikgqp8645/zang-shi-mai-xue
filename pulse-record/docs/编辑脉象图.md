# 如何编辑脉象图

> 编辑面是**本地后台（Directus）**，改完执行一次发布命令同步到远端。
> 这份文档里的每一步都在本地后台里**实测过**（2026-11-12）。

## 0. 三句话版

1. **起后台**：`node scripts/content-admin.mjs up`
2. **打开**：<http://localhost:8055/admin> —— 账号 `admin@example.com` ／ 密码 `PulseLocal2026`
3. **改完发布**：`npm run content:publish`

## 1. 一张「脉象图」是什么

| 集合（后台左侧） | 表 | 一行是什么 |
|---|---|---|
| **Content Pulse Patterns** | `content_pulse_patterns` | **一张图**（图名／出处／备注／判定探针）—— 共 50 张 |
| **Content Pulse Cells** | `content_pulse_cells` | **一张图里的一个格位** —— 每张图 18 格 ＝ 9 部位×取法 × 左右 |

18 格 ＝ 部位（寸／关／尺）× 取法（浮／中／沉）× 左右（L／R）：

```
          浮      中      沉
寸        L       L       L
关        L       L       L
尺        L       L       L
          R       R       R
```

（每个部位、每个取法各有左手和右手两个格位，所以 3×3×2 = 18。）

## 2. 打开某一张图

后台**默认已经落在参考图「清挡路」上**（讲义 p34 的 18 格实例），
所以一进「Content Pulse Cells」就能看到一屏 18 行、而不是 900 行。

换另一张图有两条路：

### 路线 A：过滤器（最直接）

1. 点右上角的**过滤器**图标（漏斗，带一个「1」角标）；
2. 把 `Pattern ID` 的值改成目标图的 id（对照表在 §5）；
3. 回车 —— 立刻变成那张图的 18 行。

> ⚠️ 这个值是**纯文本框**：Directus 12 的关系下拉只按**主键**搜，
> 填图名（「清挡路」）会得到「找不到查询结果」。
> 所以必须填 id —— 图清单里把 `id` 列显示出来就是给你对照用的。

### 路线 B：书签直达（适合收藏常用图）

每张图都有一个书签，直达地址是：

```
http://localhost:8055/admin/content/content_pulse_cells?bookmark=<预设 id>
```

⚠️ 这里的 `bookmark=` 后面是**预设在后台里的 id**（数字），**不是图名**。
用图名会得到「书签不存在」。

打开后页面标题会变成**图名**（例如「清挡路」），一眼知道自己停在哪张图上。

## 3. 改一个格位

Directus 12 的表格**没有行内编辑** —— 点格子会跳到该行的**项目编辑页**：

1. 点目标格（比如「寸 · 浮 · L」那一行的 **Term ID**）；
2. 在编辑页改字段：

| 字段 | 怎么改 | 说明 |
|---|---|---|
| **Organ**（部位） | 下拉 | 寸／关／尺 |
| **Depth**（取法） | 下拉 | 浮／中／沉 |
| **Side**（左右） | 下拉 | L／R |
| **Term ID**（用字） | **M2O 下拉**（「选择一个条目…」） | 显示的是**用字名**（大／大或顶／虚脏…共 18 个），不是 id |
| **Codes**（符号） | JSON 文本 | 一般留空；符号由用字本身决定 |
| **Group No**（组号） | 数字 | 讲稿里的「第几组」 |
| **Note**（备注） | 文本 | 改这一格的备注 |
| **Flex**（弹性） | 开关 | |
| **Pattern ID** | 只读展示 | 属于哪张图，不能改 |

3. 右上角**保存**（灰的说明还没改）；
4. 点左上角箭头回到列表。

必填项（`Pattern ID`、`Organ`、`Depth`、`Side`）在后台标了 **\***，
没填提交会被当场拦住。

## 4. 改完怎么发布

后台改的是**本地 SQLite**（`local-data/content.sqlite`），前端读的是远端 PG。
所以改完要发布一次：

```bash
npm run content:publish
```

它会：把本地库整份覆盖到远端 `content` schema 的 17 张表 → 重新生成
`src/content/*.json` 只读快照 → 记账本。

发布前想先看看会改什么：

```bash
npm run content:status      # 看远端与本地的差异
```

> ⚠️ 发布需要 `tcb login`（腾讯云 CloudBase CLI 的登录态）。没登录时会直接报
> `AUTH_FAILED：无有效身份信息`，不是内容有问题。

## 6. 已知的不顺手（照实说）

这一版能改、也能发布，但有三处体验上不理想，**都是 Directus 12 本身的行为**，
不是配错了：

| 不顺手 | 实情 | 绕法 |
|---|---|---|
| **切图要填 id** | 过滤器的 `Pattern ID` 是纯文本框，关系下拉只按主键搜，填图名搜不到 | 用上面的对照表；或用书签直达地址 |
| **没有行内编辑** | 点格子跳到项目编辑页，改一格要「点→改→保存→返回」 | 一次改多格时把编辑页开在另一个标签页 |
| **没有书签列表** | Directus 12 的界面**不列出**已保存的书签（书签图标是「把当前视图存成书签」，不是列表） | 用 §2 路线 B 的直达地址；书签 id 可以从后台 API 查 |

### 想更顺手的话，两条路（都需要先拍板）

- **给「图」加一个反向关系面板**：在图的项目页里直接列出并编辑它的 18 个格位。
  ⚠️ 这要动 `meta.one_field` —— 那正是本仓库踩过 500 坑的地方，
  得用「一个**不是列名**的名字」并加断言兜住，不能想当然填。
- **做一个 3×6 网格的专用编辑页**（Directus 扩展）：像讲义 p34 的表那样
  寸／关／尺 × 浮／中／沉 × 左右 一屏改完。代价是要引入前端扩展工程。
