# 数据层 —— JSON 为真源，Excel 为人工编辑层

> 讲清楚「数据住在哪、怎么改、怎么转、哪些不能动」。
> 面向维护者与协作者。

## 0. 一张图

```
  人工编辑                        机器消费
┌──────────────┐              ┌──────────────────┐
│ content/     │  转回         │ src/content/     │
│ 臧氏脉学-     │ ───────────▶  │ *.json           │ ── import ──▶ src/domain/*.ts
│ 用方知识库    │  excel_to_json │ （**唯一真源**）  │              │ （只留逻辑）
│ .xlsx        │ ◀───────────  │                  │ ◀─ 抽出 ──   │
└──────────────┘  excel_from_  └──────────────────┘
                    json
```

- **JSON 是唯一真源。** 代码只认 JSON。
- **Excel 是人工编辑层。** 想改内容，改 Excel，别改 JSON（改了也会被转回去覆盖）。
- **TS 只留逻辑。** 判定（`evaluate`）、查表、视图组装在 TS；照抄原文的数据在 JSON。

## 2. 常用命令

```bash
# JSON → Excel（改完 JSON 想看工作簿时）
npm run content:excel

# Excel → JSON（改完 Excel 后转回来）
npm run content:json

# 只校验、不写文件（工作簿与 JSON 是否一致）
npm run content:check

# 往返一致性 + 故意写坏验证（已挂在 npm test 里）
npm run test:e2e:excel
npm run test:e2e:excel:break
```

工作簿默认位置：`pulse-record/content/臧氏脉学-用方知识库.xlsx`

## 4. 摊平规则（`scripts/excel_schema.py` 是唯一真源）

### 4.1 数组用「单元格内换行」分隔

讲稿的方名**自带顿号**：

> 「柴鳖骨（柴胡、鳖甲、地骨皮）」

所以不能用顿号或逗号分隔数组元素，一律用**换行**（同一格内一行一个）。
读回时按行切开、去空白、丢空行。

### 4.2 嵌套拆成带外键的多张表

脉象图的三层：

```
脉象图·条目（主表，id）
   ├─ 脉象图·格位（外键 patternId，每行一个格位）
   └─ 脉象图·关系（外键 patternId，每行一个 probe）
```

**「且／或」由「组号」表达**：

- 组号留空 ＝ 该条目全部格合成一组（且）
- 组号 1、2、3 ＝ 第 1、2、3 个且组；**组内是「且」，组间是「或」**

已核：`groups` 恰好是 `cells` 的划分（每格只属一组），故此表可无损还原。

### 4.3 原文 JSON 是稀疏的

讲稿没写的字段，**键根本不存在**（不是空串）。所以列上标 `omit_empty`：
空值不产出该键 —— 往返后键集与原 JSON 完全一致。

### 4.4 符号集用逗号分隔

符号集 `0 - + ± ++ ±± ↑ | # X TTT DDX` 里**没有逗号**，逗号分隔是安全的。
（注意 `|` 本身是个符号，但它不是分隔符。）

## 5. 不能动的纪律

这些是本仓库的既有纪律，搬进数据层后**一条都不放松**：

1. **方名照录** —— 不改成现代教材方名。同名不同名的**并列**登记，不替读者选一个。
2. **剂量不换算** —— 讲稿比例制与同和堂版的克是两套。
3. **出处必标** —— 每条都带 `source`，格式「讲稿 2010·第N讲」「讲义 2026-10·pNN」。
4. **转述不加引号** —— 只有逐字引用才加引号。
5. **讲稿没写的一律留空** —— 不补写、不臆造。
6. **不替读者加减方、不下诊断** —— 页面已声明「不构成诊断」。
7. **三套资料线不合并** —— 讲稿／讲义／同和堂版各自标注，体质命名体系不互换。

## 6. 出错会怎样

还原脚本**宁可报错也不猜**。以下情况直接报错退出（不写文件）：

| 情况 | 错误信息 |
|---|---|
| 主键为空 | `主键（id）为空` |
| 主键重复 | `主键「xxx」重复` |
| 父 id 悬空 | `条目ID「xxx」在「脉象图·条目」里不存在` |
| 用字未定义 | `用字「xxx」不在「脉象用字」表里` |
| 组号非正整数 | `组号「xxx」不是正整数` |
| 同一关系前后用语不一致 | `关系「xxx」原文用语前后不一致` |

这些都有对应的「故意写坏」测试盯着（`scripts/e2e/excel_roundtrip_break.py`），
确保它们**真的会报错**，而不是把坏数据当好数据写进 JSON。

## 7. 加一张新表时

1. 在 `scripts/excel_schema.py` 里加 `SheetDef`（列、类型、摊平规则）；
2. 在 `excel_from_json.py` / `excel_to_json.py` 里接上数据路径；
3. **加往返测试**：新表必须逐字段往返一致；
4. 若新表有嵌套结构，先想清楚摊平方式（外键＋序号），再动手。

改完跑 `npm test` —— 往返测试会立刻告诉你摊平规则有没有写错。
