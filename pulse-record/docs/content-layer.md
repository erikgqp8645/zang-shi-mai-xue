# 数据层 —— 真源、四条编辑路线与纪律

> 讲清楚「数据住在哪、我要改一个东西该走哪条路、哪些不能动」。
> 面向维护者与协作者。

三个位置，各管各的（细节见 **[`content-publish.md`](./content-publish.md)**）：

| 位置 | 角色 | 谁能写 |
|---|---|---|
| `local-data/content.sqlite` | **编辑真源**（17 张表） | 只有使用者，经本地后台 |
| 远端 PG `content.*` | **线上真源** | 只有发布命令（一次事务） |
| 仓库 `src/content/*.json` | **可读快照**（派生） | 只有发布命令 |

> ⚠️ 快照**不是编辑面** —— 手改会被下一次发布覆盖。
> ⚠️ 「改完还没发布」＝**草稿**；远端 PG 里的是**已发布**。两者本来就不一样。

## 1. 四条编辑路线

**先看你要改什么，再选路线。** 四条路改的是**不同的层**，别搞混。

| # | 路线 | 适合改什么 | 入口 | 生效范围 |
|---|---|---|---|---|
| ① | **网站端 ③ 编辑器** | 用方条目的条件文字／治法／**方名标签**／显示与否 | 浏览器里点着改（管理员账号） | 覆盖层 → 刷新即生效 |
| ② | **脉象图编辑器** | 某一条目的脉象图（格位／组号／关系型要求） | 网页里逐格勾选 | 覆盖层 → 刷新即生效 |
| ③ | **本地后台（Directus）** | **全部 17 张内容表**（含 ① ② 覆盖不到的部分） | `npm run content:admin` | 草稿 → 发布命令 → 远端 |
| ④ | **管理员命令行** | 精确改单条／**删条目**／导出审计／批量导入 | `npm run admin -- library …` | 覆盖层 → `library apply` → 快照 |

### ① 网站端 ③ 编辑器

- **入口**：网站端 ③「用方知识库」里，每条上的 ✎／✕，方名标签上的 ✎／✕／＋。
- **接口**：`PATCH /api/library/entries/:kind/:id`、`DELETE …`、
  `POST …/restore`、`POST …/revive`（见 `src/api/library.ts`）。
- **权限**：写接口**仅管理员**；读接口登录即可（知识库是公共资料）。
- **子项级**：方名标签（`formulas[]`）能**单独**改／删／加 ——
  删一个标签**只删那一个**，别的方名照旧（`src/domain/library-chips.mjs`）。

### ② 脉象图编辑器

- **入口**：③ 里的脉象图区块（`src/components/PatternEditor.tsx`）。
- 改的是**某一条目**的脉象图：格位（用字／组号／柔性）与关系型要求。
- ⚠️ 它是**覆盖层**，不改仓库快照；要进内容层发布，走 ③ 的后台。

### ③ 本地后台（Directus）

```bash
npm run content:admin          # 起／停／看状态（容器 pulse-directus，端口 8055）
npm run content:admin:init     # 按 schema 的 fk 声明自动配关系／字段／视图预设（幂等）
```

后台界面全中文，17 张表全部接管。**这是唯一能改「整份内容」的地方**
（① ② 只覆盖层，④ 只覆盖层）。

### ④ 管理员命令行

```bash
npm run admin -- library --help        # 完整用法
npm run admin -- library show rule fx2-sanjiao-wuli
npm run admin -- library set rule fx2-sanjiao-wuli --set "condition=变脉无力"
npm run admin -- library del  rule fx2-sanjiao-wuli      # 写墓碑，可撤销
npm run admin -- library apply                          # 合并回 src/content/*.json
```

覆盖层语义与 ① ② **同一套**（同一张 `library_items` 表），详见
[`library-admin.md`](./library-admin.md)。

| 文件 | 内容 | 条数 |

| `src/content/doses.json` | 同和堂版成方（药味＋**克**）＋ 科中＋ 成方↔科中对照 | 49 ＋ 17 ＋ 15 |
| `src/content/formula-reference.json` | 讲义 p42 用方表 ＋ 方名别名对照 ＋ 讲稿草稿方 | 28 ＋ 15 ＋ 1 |
| `src/content/formula-rules.json` | 用方条目（条件文字／治法／方剂／出处／原文） | 61 |
| `src/content/pulse-terms.json` | 原文用字 → 符号集 | 18 |
| `src/content/symbols.json` | 讲义 p34 的固定符号集（`0`＝无、`++`＝有力、`↑`＝顶……） | 14 |
| `src/content/pulse-groups.json` | 脉位组合（双关同治、肝肺同治……） | 7 |
| `src/content/pulse-patterns.json` | 脉象图（每条用方条目一张） | 50 |
| `src/content/library-settings.json` | 知识库区块自己的显示设置 | 1 |

每份内容另有一份 **JSON Schema**（`src/content/schema/*.schema.json`）——
那是**编辑面与校验的契约**：加字段、改类型、必填与枚举都在那儿声明。

> ⚠️ **剂量有两套单位，不可换算、不可合并**：
> 讲稿 2010 是**比例制**（如「熟地5」），同和堂版是**克**。界面分栏标注出处。

> ⚠️ **脉象图多了一层「网页手改」**：
> 快照里的 JSON 是**只读基线**；使用者在网页上填的脉象图存在服务端的
> `formula_patterns` 表（覆盖层），**不写回 JSON**。规则：某条目有覆盖就整条接管，
> 没有就用基线；「恢复默认」＝删掉覆盖行。

## 3. 覆盖层语义（① ② ④ 共用一套）

覆盖层（`library_items` 表）按 `(kind, item_id)` **整条接管**：

| 覆盖层里 | 结果 |
|---|---|
| 有行且 `deleted=0` | 用这一行的 payload **整条接管**该基线条目 |
| 有行且 `deleted=1` | **墓碑**：该条目在结果里消失 |
| 没有行 | 保持内置基线 |

⚠️ 为什么要墓碑：覆盖层是「有行就用覆盖层」。若删除只表现为「没有行」，
读回来就等于「没改过」→ 静默回落到基线，管理员刚删掉的条目又冒出来。

⚠️ **三个动词别搞混**：

| 动作 | 撤的是 | 结果 |
|---|---|---|
| `restore` | 覆盖层里**这一行** | 回到内置基线的样子 |
| `revive` | **那一次删除** | 把删掉的条目原样放回来 |
| `set` | — | 改内容 |

## 4. 不能动的纪律

这些是本仓库的既有纪律，搬进数据层后**一条都不放松**：

1. **方名照录** —— 不改成现代教材方名。同名不同名的**并列**登记，不替读者选一个。
2. **剂量不换算** —— 讲稿比例制与同和堂版的克是两套。
3. **出处必标** —— 每条都带 `source`，格式「讲稿 2010·第N讲」「讲义 2026-10·pNN」。
4. **转述不加引号** —— 只有逐字引用才加引号。
5. **讲稿没写的一律留空** —— 不补写、不臆造。
6. **不替读者加减方、不下诊断** —— 页面已声明「不构成诊断」。
7. **三套资料线不合并** —— 讲稿／讲义／同和堂版各自标注，体质命名体系不互换。
8. **宁可不写，也不写半坏数据** —— 发布自检不过就中止；引用断了不写盘。

## 5. 加一张新表时

1. 在 `src/content/schema/` 加一份 **JSON Schema**（字段、类型、必填、枚举、外键）；
2. 在 `server/content-schema.mjs` 登记（表名、主键、列序）；
3. 跑 `npm run content:seed` 灌进本地库，`npm run content:admin:init` 配后台；
4. **加断言**：schema ↔ 库结构必须对得上（`npm run test:e2e:content`）。

> ⭐ **别在 TS 里再抄一份。** 数据一旦进了 `src/content/*.json`，
> `src/domain/*.ts` 就只能 `import` 它，不能再写一份字面量 ——
> 那样会变成两处真源，改了一处另一处悄悄对不上。
