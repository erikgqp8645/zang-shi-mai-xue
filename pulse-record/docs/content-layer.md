# 数据层 —— JSON 为真源，Excel 为人工编辑层

> 讲清楚「数据住在哪、怎么改、怎么转、哪些不能动」。
> 面向维护者与协作者。

## 0. 一张图

```
  人工编辑                        机器消费
┌──────────────┐              ┌──────────────────┐
│ content/     │  转回         │ src/content/     │
│ 臧氏脉学-     │ ───────────▶  │ *.json           │ ── import ──▶ src/domain/*.ts
│ 用方知识库    │  excel_to_json │ （**唯一真源**）  │              │ （只留逻辑）
│ .xlsx        │ ◀───────────  │                  │ ◀─ 抽出 ──   │
└──────────────┘  excel_from_  └──────────────────┘
                    json
```

- **JSON 是唯一真源。** 代码只认 JSON。
- **Excel 是人工编辑层。** 想改内容，改 Excel，别改 JSON（改了也会被转回去覆盖）。
- **TS 只留逻辑。** 判定（`evaluate`）、查表、视图组装在 TS；照抄原文的数据在 JSON。

## 2. 常用命令

```bash
# JSON → Excel（改完 JSON 想看工作簿时）
npm run content:excel

# Excel → JSON（改完 Excel 后转回来）
npm run content:json

# 只校验、不写文件（工作簿与 JSON 是否一致）
npm run content:check
# ⚠️ 改了「脉象图·条目」表的「图名」列后，要按顺序跑：
#    content:json（图名进 JSON）→ content:excel（tab 名跟上）。
#    只跑 content:json 的话，content:check 会报「sheet 名与图名不一致」。

# 往返一致性 + 故意写坏验证（已挂在 npm test 里）
npm run test:e2e:excel
npm run test:e2e:excel:break

# 重新生成练习册（主工作簿改了之后）
npm run content:exercise

# 验收练习册（填完一格就能验一格）
npm run content:exercise:check

# 重新生成填写流程图里的矩阵示意（工作簿改了之后）
npm run content:flowchart

# 只校验流程图页面与工作簿是否一致
npm run content:flowchart:check
```

工作簿默认位置：`pulse-record/content/臧氏脉学-用方知识库.xlsx`

## 3. 工作簿长什么样

工作簿共 **65 个 sheet** ＝ **15 张通用表** ＋ **50 张脉象图矩阵**。

### 3.1 通用表（15 张）

| 表 | 行数 | 是什么 |
|---|---|---|
| 说明 | 16 | 怎么改这份工作簿；每张表的列说明与编辑约定 |
| 方剂·讲稿2010 | 30 | 讲稿 2010 的方剂条目 |
| 成方·同和堂版 | 49 | 同和堂版成方（克） |
| 科学中药比例 | 17 | 同和堂版 p4「科中」 |
| 成方↔科中对照 | 15 | 哪个成方用哪条科中比例 |
| 讲义p42用方表 | 28 | 讲义 p42 的依脉用方表（只有处方名＋脉象） |
| 方名别名对照 | 15 | 同一张方在两条资料线的不同叫法 |
| 讲稿草稿方 | 1 | 讲稿给了方子但没给剂量 |
| 脉象用字 | 18 | 原文用字 → 符号集（**带「符号含义」列**：`++＝有力`） |
| 符号表 | 14 | 讲义 p34 的固定符号集 —— 不知道 `++` 是什么就查这张 |
| 脉位组合 | 7 | 双关同治、肝肺同治、双寸…… |
| 用方条目 | 61 | 依脉用方的 61 条（条件文字是**原文用语**） |
| 脉象图·条目 | 50 | 每条用方条目的元信息（ID／**图名**／路线／条件／出处／出入） |
| 脉象图·格位 | 96 | ⚠️ **派生表**（由矩阵摊平），不是编辑面 |
| 脉象图·关系 | 39 | 画不成单格的条件（左右同名取法不同、任意格变脉……） |

### 3.2 脉象图矩阵（50 张，`P01-三焦疗法·肾虚` … `P50-肝心同治·挡路六`）

**体例照讲义 2026-10 p34 的记录表** —— 左列部位／取法，右边左手、右手两列，
9 行（寸浮／寸中／寸沉／关浮／关中／关沉／尺浮／尺中／尺沉）。
和讲义上的图对得上。

⭐ **sheet 名＝`P序号-图名`** —— 序号后面跟的是**图名（方剂名）**，
翻 tab 栏一眼就知道那张表是哪个方子的（如 `P04-清挡路`、`P05-引火归元·上盛下虚`）。
图名的真源是「脉象图·条目」表的**图名**列。

```
第 1 行   顶部提示（填写说明摘要）
第 2 行起 表头区：条目ID（校验用）｜路线｜触发条件｜出处｜与条件文字的出入｜关系型要求
          ⚠️ 除「条目ID」外都是**只读副本**，真源在「用方条目」表／「脉象图·关系」表
列头行    部位｜取法｜左手｜右手｜左组号｜右组号｜左格备注｜右格备注｜左柔性｜右柔性
9 行数据  寸（合并 3 行）｜浮中沉｜左手用字｜右手用字｜…
```

⭐ **矩阵是脉象图的唯一编辑面。**
「脉象图·格位」长表由矩阵**派生** —— 在长表里改脉象，转回 JSON 时会被矩阵覆盖。
往返测试里有一条专门盯着这个（清空长表后还原结果必须不变）。

### 3.3 怎么填：三种地方都能查到

| 想知道 | 去哪看 |
|---|---|
| 某一列怎么填 | **悬停该列的列头** —— Excel 批注（内容与「说明」表同源） |
| 某张表整体怎么用 | 「说明」表对应那一行（「这张表是什么」＋「怎么编辑」） |
| 矩阵的格子怎么填 | 矩阵 sheet **顶部提示行** ＋ 各列批注 |

⚠️ 「符号含义」列是**算出来的**（把「符号集」翻成中文），只读；
要改含义去「符号表」改「名称」，要改可接受的取值就改「符号集」。

### 3.4 审核建议的顺序

1. `用方条目` —— 条件文字是原文用语，先看它对不对；
2. `P04-清挡路` … `P50-肝心同治·挡路六` 矩阵 —— 逐条核对「条件文字 ↔ 脉象图」是否一致；
3. `脉象图·关系` —— 关系型要求（画不成单格的那些）。

矩阵 sheet 名里的**序号是权威的**（条目 ID 超 31 字符会被 Excel 截断），
所以序号不要改；**图名可以改**，但要去「脉象图·条目」表改，然后跑
`content:json` → `content:excel` 让 tab 名跟上。
表头区的「条目ID」与序号对不上时，转回 JSON 会直接报错。

## 4. 摊平规则（`scripts/excel_schema.py` 是唯一真源）

### 4.1 数组用「单元格内换行」分隔

讲稿的方名**自带顿号**：

> 「柴鳖骨（柴胡、鳖甲、地骨皮）」

所以不能用顿号或逗号分隔数组元素，一律用**换行**（同一格内一行一个）。
读回时按行切开、去空白、丢空行。

### 4.2 嵌套拆成带外键的多张表

```
脉象图·条目（主表，id）
   └─ 脉象图·关系（外键 patternId，每行一个 probe）
脉象图·格位  ← 派生（由矩阵摊平），不参与读回
```

### 4.3 脉象图：矩阵 ↔ 长表

矩阵是**编辑面**，长表是**派生视图**：

- 写：JSON 的 `cells` 按矩阵版面摊平成长表；
- 读：**只认矩阵**，长表重新派生。

矩阵的一格 ↔ 长表的一行：

| 矩阵 | 长表列 |
|---|---|
| 左手／右手 | 用字 |
| 左组号／右组号 | 组号 |
| 左格备注／右格备注 | 备注 |
| 左柔性／右柔性 | 柔性 |

**「且／或」由「组号」表达**：

- 组号 1、2、3 ＝ 第 1、2、3 个且组；**组内是「且」，组间是「或」**
- **左右两列的组号共用同一个编号空间** —— 左格与右格都填 1，它们就是**同一组**
  （都要满足），不是两组（实测：50 张矩阵 sheet 全部按此规则还原）
- **填了用字就必须填组号** —— 不填的话这一格会被悄悄丢出任何组，
  图上还留着用字，看着像有要求其实没有 ⇒ 读回时**报错**

已核：`groups` 恰好是 `cells` 的划分（每格只属一组），故此表可无损还原。

### 4.4 原文 JSON 是稀疏的

讲稿没写的字段，**键根本不存在**（不是空串）。所以列上标 `omit_empty`：
空值不产出该键 —— 往返后键集与原 JSON 完全一致。

### 4.5 符号集用逗号分隔

符号集 `0 - + ± ++ ±± ↑ | # X TTT DDX` 里**没有逗号**，逗号分隔是安全的。
（注意 `|` 本身是个符号，但它不是分隔符。）

### 4.6 格位顺序是规范化的

`cells` 的顺序**由矩阵版面唯一决定**：左手 9 行读完，再右手 9 行；
组内顺序与 `cells` 同序。顺序无语义（cells 是集合、组内是「且」、组间是「或」），
所以定一份规范，免得同一份数据有两种排列。

往返测试里有一条断言盯着（磁盘 JSON 的顺序必须＝矩阵派生序）。

## 5. 不能动的纪律

这些是本仓库的既有纪律，搬进数据层后**一条都不放松**：

1. **方名照录** —— 不改成现代教材方名。同名不同名的**并列**登记，不替读者选一个。
2. **剂量不换算** —— 讲稿比例制与同和堂版的克是两套。
3. **出处必标** —— 每条都带 `source`，格式「讲稿 2010·第N讲」「讲义 2026-10·pNN」。
4. **转述不加引号** —— 只有逐字引用才加引号。
5. **讲稿没写的一律留空** —— 不补写、不臆造。
6. **不替读者加减方、不下诊断** —— 页面已声明「不构成诊断」。
7. **三套资料线不合并** —— 讲稿／讲义／同和堂版各自标注，体质命名体系不互换。

## 6. 出错会怎样

还原脚本**宁可报错也不猜**。以下情况直接报错退出（不写文件）：

| 情况 | 错误信息 |
|---|---|
| 主键为空 | `主键（id）为空` |
| 主键重复 | `主键「xxx」重复` |
| 父 id 悬空 | `条目ID「xxx」在「脉象图·条目」里不存在` |
| 矩阵：用字未定义 | `用字「xxx」不在「脉象用字」表里` |
| 矩阵：组号非正整数 | `组号「xxx」不是正整数` |
| 矩阵：表头 ID 与序号不符 | `表头写的条目ID 是「xxx」，但序号 NN 对应的是「yyy」—— 两者不一致` |
| 矩阵：漏了一个 sheet | `矩阵里没有条目「xxx」的 sheet` |
| 同一关系前后用语不一致 | `关系「xxx」原文用语前后不一致` |

这些都有对应的「故意写坏」测试盯着（`scripts/e2e/excel_roundtrip_break.py`，9 类坏数据），
确保它们**真的会报错**，而不是把坏数据当好数据写进 JSON。

## 7. 加一张新表时

1. 在 `scripts/excel_schema.py` 里加 `SheetDef`（列、类型、摊平规则）；
2. 在 `excel_from_json.py` / `excel_to_json.py` 里接上数据路径；
3. **加往返测试**：新表必须逐字段往返一致；
4. 若新表有嵌套结构，先想清楚摊平方式（外键＋序号），再动手。

改完跑 `npm test` —— 往返测试会立刻告诉你摊平规则有没有写错。

> ⭐ **别在 TS 里再抄一份。** 数据一旦进了 `src/content/*.json`，
> `src/domain/*.ts` 就只能 `import` 它，不能再写一份字面量 ——
> 那样会变成两处真源，改了一处另一处悄悄对不上。
> （`symbols.ts` 就是这么从「硬编码 14 个符号」改成读 `symbols.json` 的。）
