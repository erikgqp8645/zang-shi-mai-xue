## 1. 微信后台 ·《用户隐私保护指引》（⬜ 不用勾隐私类型）

**位置**：小程序后台 → 设置 → 用户隐私保护指引 → 去更新。

### 1.1 隐私接口 —— **一项都不用勾**

| 勾选 | 对应接口 | 触发时机 |
|---|---|---|
| （无） | —— | 2026-11-05 起上线包**不再调用任何隐私接口**：原来的「存到相册」「复制 Markdown／CSV」三个导出选项，连同 `saveImageToPhotosAlbum`、`setClipboardData` 一起删掉了 |

**为什么不用勾**：勾了就是「声明了没用」。微信审核会对照声明与实际调用，
多勾一项反而可能被当成不实声明。

⚠️ **例外**：**原生回退工程 `miniprogram/` 里仍带**这两个接口（它是本地兜底，不上传）。
若哪天改用它上线，才需要勾「相册（仅写入）」与「剪切板」。

### 1.2 不用勾的（及为什么）

这些**代码里根本没有调用**，勾了反而是「声明了没用」：

| 不勾 | 依据 |
|---|---|
| 位置信息 | 无 `getLocation` / `getFuzzyLocation` 调用 |
| 通讯录 | 无 `chooseContact` / `chooseAddress` 调用 |
| 摄像头 / 麦克风 | 无 `camera` / `record` 相关调用 |
| 读取相册 | 无 `chooseMedia` / `chooseImage` 调用（连写入的也没有了） |
| 手机号 | 个人主体不支持 `getPhoneNumber`；代码里没调 |
| 昵称 / 头像 | 无 `getUserProfile` / `getUserInfo` / `chooseAvatar` 调用 |
| 蓝牙 / 通讯 / 交易 | 无相关调用 |

### 1.3 收集的用户信息

如实地写「用户输入内容」这一类：

| 项 | 怎么写 |
|---|---|
| 用户输入内容 | > 使用者自行录入的病例资料：患者姓名、就诊记录、脉象格值、用药记录。仅用于保存与展示使用者自己的脉诊记录，不用于画像、不用于广告。 |
| 账号信息 | > 使用者自设的登录名、显示名称；密码以 scrypt 加随机盐的哈希形式存储，服务器上不保存明文密码。 |

**不要**勾「微信昵称」「微信头像」「手机号」—— 我们都没取。

### 1.4 第三方 SDK（⬜ **走 cloud 路线要填**）

当前微信端 **TRANSPORT = 'cloud'**（`wx.cloud.callFunction`）→ **必须**在这里补声明：

| 填什么 | 怎么写 |
|---|---|
| SDK 名称 | 腾讯云 CloudBase（云开发） |
| 用途 | > 用于调用使用者自己的云端服务，保存其自行录入的脉诊记录。仅传输使用者输入的病例数据与登录凭证，不用于画像、不用于广告。 |

⚠️ **不填会怎样**：微信审核会查第三方 SDK 声明，声明与实际调用对不上是常见退回原因。
（`wx.cloud` 属于平台提供的云开发能力，但用了它就要在「第三方 SDK」里如实写明。）

> 只有改走 `TRANSPORT='request'`（自己服务器）时才真的没有第三方 SDK，这一栏才可以不填。

### 1.5 保存期限与删除方式

| 项 | 怎么写 |
|---|---|
| 保存期限 | > 账号与病例数据在服务器上持续保存，直至使用者自行删除或注销账号。 |
| 删除方式 | > 使用者可在小程序内逐条删除病例记录；「我的」页可解绑微信身份；注销账号（连带删除全部数据）请联系运营者。 |

### 1.6 配完之后的两件事

1. **基础库最低版本**（后台 → 开发管理 → 基础库）建议设 **2.32.3 或以上** ——
   低于这个版本微信不会自动弹隐私协议，调用隐私接口会直接失败。
   （现在上线包**不调隐私接口**了，这条只是以防以后加功能。）
2. 微信会在**首次调用隐私接口时自动弹协议**。目前**没有这样的调用**，所以不会有弹窗 ——
   以后若加回导出功能，代码里要重新识别两种错误并给出可操作的提示。

## 2. 微信后台 · 服务器域名（☐ 走 cloud 路线不需要；改走 request 才要等备案）

**位置**：小程序后台 → 开发管理 → 开发设置 → 服务器域名 → **request 合法域名**。

> ⚠️ **当前主线走 `TRANSPORT='cloud'`（`wx.cloud.callFunction`）—— 不经过 `Taro.request`，
> 所以整节这一栏不需要填，也不需要 ICP 备案。**
> 微信对云函数调用**不做合法域名校验**，这是 cloud 路线的最大好处。
> 只有当你决定改走 `TRANSPORT='request'`（比如备案终于下来了、想把后端挪出 CloudBase）才需要下面这些。

微信的硬要求（走 request 路线时）：

- 必须是 **https**
- 域名**必须已 ICP 备案**（主体与小程序主体一致）
- **不能带端口、不能是 IP**

所以开发阶段用的是 `http://127.0.0.1:5178` / 局域网 IP，**上线包不能带着它**。
上线构建时注入正式域名：

```bash
cd pulse-record
PULSE_API_BASE=https://<你的备案域名> npm run mp:taro:build
```

注入已实测：产物 `common.js` 里的默认地址会变成注入的域名；
不注入就是本机默认值（`src/utils/config.ts`）。
「我的」页里也能改（存在本地存储），所以联调包与正式包可以并存。

## 2.5 关联 CloudBase 环境（⬜ **上线的头号阻塞**）

> **2026-11-06 实测**：环境 `ambitious-parrot-d7ehh7x0fd9d680` 的 `UserInfo` 仍是 `{}` ——
> **还没跟小程序 appid 关联**，所以 `wx.cloud.callFunction` 会报
> `errCode: -501000 | errMsg: Environment not found`。
>
> **没有公开 API 能代劳**（已穷举 CloudBase 管控面全部 Action：
> `ModifyEnv` 虽然认 `WxAppId` 参数，但没做过账号级绑定时它是空操作，读回来仍是空）。
> **必须本人在微信侧点。**

### 2.5.1 第一步：把「微信公众平台」关联到腾讯云账号

1. 打开 <https://tcb.cloud.tencent.com/dev> → 右上角**用户名下拉** → 「**账号信息**」 → 「**账号中心**」
   （⚠️ 子账号必须切到**主账号**，这一步在子账号下没有入口）
2. 左侧「**登录方式**」→ 找到「**微信公众平台**」→ 点右侧「**关联**」
3. 弹窗扫码 → 用微信登录 → 出现「账号关联」窗口 → 点「**去授权**」→ 确认

### 2.5.2 第二步：在开发者工具里把环境转成「我的环境」

4. 微信开发者工具 → 顶部「**云开发**」 → 「**设置**」 → 「环境名称」下拉 → 「**管理我的环境**」
5. 侧边栏点「**使用已有腾讯云环境**」→ 选 `ambitious-parrot-d7ehh7x0fd9d680` → 确认「**环境转换**」→ 扫码验证

### 2.5.3 怎么确认成了

```bash
cd pulse-record
set -a; source /tmp/pg.env; set +a
node -e "
import('./scripts/lib/tcb-capi.mjs').then(async (m)=>{
  const r = await m.callTcb('DescribeEnvs', { EnvId: 'ambitious-parrot-d7ehh7x0fd9d680' });
  const e = r.EnvList[0];
  console.log('WxAppId =', e.UserInfo?.WxAppId);
})"
```

`WxAppId` 打出 `wx3a21eb903a16cbc4` 就是成了；
仍是 `undefined` 就回去看上面哪一步没点到位。

> 关联之前，小程序**仍然能跑**（2026-11-06 加的兜底：云调用传输层失败 → 自动改走直连），
> 但直连的默认地址是 `http://127.0.0.1:5178` ——
> 在开发者工具里那恰好是你本机的后端（所以看着正常），
> **一上传到微信，`127.0.0.1` 指的是手机自己，必然连不上**。
> → **先关联，再上传。**

## 6. 真机联调要点（不用等备案时先做）

> ⚠️ 下面这套是**当前主线（Taro 工程 `taro/`）**的做法。
> 原生回退工程 `miniprogram/` 用的是 `npm run mp:dev`（那个脚本自己会把 HOST 设成 `0.0.0.0`），
> **别把两条线混起来**。

### 6.1 电脑侧：一条命令

```bash
cd pulse-record
npm run dev:lan          # = HOST=0.0.0.0 node scripts/dev.mjs
```

**后端默认只听 `127.0.0.1`，外部访问不到** —— 这是「本机能跑、手机连不上」最常见的原因。
2026-11-06 实测：后端只听回环时 `curl http://<局域网IP>:5178/` 直接连不通（返回 000）。

### 6.2 先在手机上分诊（30 秒，省掉后面所有猜测）

用**手机 Safari** 打开 `http://<电脑局域网IP>:5178/api/patients`：

| 结果 | 说明 |
|---|---|
| 出一段 JSON（`{"patients":[…]}`） | 网络通 → 往下走 |
| 打不开 | ① 电脑防火墙（macOS 会弹「node 想要接受传入连接」→ **选允许**）② 手机与电脑不在同一 WiFi ③ 局域网 IP 变了（`ipconfig getifaddr en0`） |

### 6.3 开发者工具侧

| 项 | 做法 |
|---|---|
| 打开哪个工程 | **`pulse-record/taro`**（不是 `miniprogram/`）—— `miniprogramRoot` 指向 `dist/` |
| 不校验合法域名 | 详情 → 本地设置 → 勾「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」（`project.config.json` 里已有 `urlCheck: false`，工具里要再确认一次） |

### 6.4 小程序里改服务器地址（**不用重新编译**）

「我的」页 → 服务器地址 → 填 `http://<电脑局域网IP>:5178` → 「测试连接」→ 保存。

- 改的是**这台手机本地**（存 `pulse.apiBase`），换 IP 后回来改一次就行。
- 编译期默认值是 `http://127.0.0.1:5178` —— 在手机上，`127.0.0.1` 指的是**手机自己**，所以必须改。

### 6.5 登录要不要

**单机模式（默认 `npm run dev:lan` 就是）不用登录** ——
服务端 `server/index.mjs` 里 `if (SINGLE_USER) return await getLocalUser(db)`，
所有请求都算内置单机账号，`/api/auth/me` 返回 `wechatBound: false`。
要验「小程序用网站账号＋密码绑定微信」那条路，才用 `npm run dev:multi`。

## 7. 审核常见退路（对照着查）

| 症状 | 根因 | 处置 |
|---|---|---|
| 真机所有请求超时 / 连不上（走 request 路线） | request 合法域名没配，或用了 IP／端口／http | §2 |
| 真机所有请求超时 / 连不上（走 cloud 路线） | 环境没跟小程序关联，`-501000` 后兜底直连 `127.0.0.1`（指手机自己） | §2.5 |
| 隐私弹窗不出现 | 现在**没有隐私接口调用**，不弹是正常的 | §1.1 |
| 审核说「找不到隐私政策」 | 小程序内没有可见入口 | 已加（§4.2） |
| 审核说「功能与类目不符」 | 类目选错 | §3 |
| 审核说「第三方 SDK 未声明」 | 走 cloud 路线却没填「腾讯云 CloudBase」 | §1.4 |
| 审核说「隐私政策内容不完整」 | 隐私政策页还写着「（待填写）」，改了没重新编译 | §5.5.5 第 4 项 |
| 提审提示需要手机号／用户信息授权 | 个人主体不支持，或代码里没调 | 不用管（§1.2） |
